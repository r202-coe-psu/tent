# บันทึกการแก้ไขระบบ SmartShelter (V8)

_อัปเดตล่าสุด: 23 กรกฎาคม 2569_

เอกสารนี้สรุปทุกจุดที่ตรวจพบปัญหาและสั่งแก้ไขในระบบ SmartShelter (ระบบบริหารจัดการศูนย์พักพิงและคลังสิ่งของช่วยเหลือภัยพิบัติ) เรียงตามโมดูล/หน้าจอ พร้อมสถานะล่าสุดของแต่ละรายการ

สถานะที่ใช้ในเอกสาร:
- ✅ แก้แล้ว ยืนยันผลด้วยภาพหน้าจอจริง
- 🟡 ส่ง prompt ไปแก้แล้ว แต่ยังไม่ได้ยืนยันผลด้วยภาพหน้าจอ
- ⏳ ออกแบบ/ตกลงแนวทางไว้แล้ว แต่ยังไม่ได้ส่ง prompt ไปแก้จริง

---

## 1. ระบบรับบริจาคหลังบ้าน (Donation Board / Back-office)

### 1.1 ปุ่ม "อนุมัติรับเข้าคลัง" กดไม่ได้ ✅
ปัญหา: กดปุ่มอนุมัติแล้วไม่มีอะไรเกิดขึ้น ไม่มีข้อความแจ้งเตือนใดๆ
สาเหตุจริง: ยังไม่ได้จับคู่ Item Mapping ให้ครบ หรือยังไม่ติ๊ก "ผ่านการตรวจสอบแล้ว"
การแก้ไข: เพิ่มข้อความแจ้งเตือนบนหน้าจอเมื่อกดแล้วไม่ผ่านเงื่อนไข ระบุชัดว่าขาดอะไร (เช่น "ยังจับคู่ข้อมูลสินค้าไม่ครบ / ยังไม่ได้ติ๊กผ่านการตรวจสอบ")

### 1.2 แยกหน้า "ตรวจสอบรายการบริจาค" เป็น 2 หน้าตามสถานะจริง ✅
ปัญหา: หน้าเดียวปนกันทั้งการตัดสินใจอนุมัติ/ปฏิเสธ และการกระทบยอดของจริงที่รับเข้า ทำให้มีช่องกรอกจำนวนรับจริงทั้งที่ของยังไม่มาถึง
การแก้ไข: แยกเป็น
- "รอการประเมิน (Pending Review)" — หน้าตัดสินใจอย่างเดียว (อนุมัติคำขอ / ปฏิเสธคำขอ / ประสานงานส่งต่อ) ไม่มีช่องกรอกจำนวน
- "กำลังตรวจรับ (Verifying Drop-off)" — หน้ากระทบยอดจริง (จำนวนรับจริง, Item Mapping, โซนจัดเก็บ, วันหมดอายุ, อนุมัติรับเข้าคลังสร้าง Lot+Ledger จริง)

### 1.3 ปุ่ม "ประสานงานส่งต่อ" (Redirect) ✅
กำหนดพฤติกรรม: ไม่สร้าง Lot/Ledger ที่ศูนย์นี้ เปิด modal ให้เลือกศูนย์ปลายทาง+หมายเหตุ สร้าง Ticket โอนย้ายข้ามศูนย์ ปิดรายการบริจาคเป็น "ส่งต่อศูนย์อื่นแล้ว"

### 1.4 ทดสอบ 3 เคสการรับบริจาค (บริจาคตามรายการ / บริจาคของอื่นๆ / Walk-in) ✅
ทดสอบ Flow ทั้ง 3 ทางจนสำเร็จ พบและแก้บั๊ก skip-Pending-Review ที่ไม่ยอมข้ามไปสถานะ "รอรับของ" ตามเงื่อนไขที่ถูกต้อง

### 1.5 หน้าปุ่มทั้งหมดกดไม่ได้ (Whole-page lockup) ✅
สาเหตุ: ข้อมูลเป็น mock ที่ไม่มี record จริงให้ผูก
การแก้ไข: เพิ่ม dropdown เลือกรายการที่ Scan Station โดยตรง (แทนพึ่งพา QR อย่างเดียว) รองรับกรณี QR หาย/แบตหมด

### 1.6 Force Cut-off (ปิดด่วน) ต่อรายการสินค้า ✅
ออกแบบ: มีช่องเหตุผลบังคับกรอก, ปฏิเสธอัตโนมัติเฉพาะคำขอที่ยังอยู่สถานะ "รอการประเมิน", ไม่แตะรายการที่อยู่ "รอรับของ/กำลังตรวจรับ" ไปแล้ว, บันทึกเหตุผลเข้ารายงานความโปร่งใส

### 1.7 บั๊ก Cold-chain ไม่ถูกเช็คก่อนออก QR ✅
ปัญหา: บริจาค "เนื้อไก่สด" (ของต้องแช่เย็น) แต่ระบบข้ามไปออก QR ทันที ทั้งที่ควรถูกส่งเข้า "รอการประเมิน" ก่อนเสมอ
สาเหตุ: Item Master ไม่ได้ตั้งค่า flag "ต้องแช่เย็น" หรือ logic ไม่ได้เช็คค่านี้
การแก้ไข: ตั้งค่า flag ให้ถูกต้อง + แก้ logic ให้เช็คก่อน skip เสมอ ทดสอบซ้ำแล้วได้ผลถูกต้อง (ขึ้นหน้าจอสีส้มรอประเมิน ไม่มี QR)

### 1.8 ข้อมูลซ้ำ "เนื้อไก่สด" ในหน้ารายละเอียดศูนย์ ✅
ลบแถวซ้ำออก เหลือ 1 รายการตามจริง (ต้องแก้ 2 รอบ เพราะรอบแรกอ้างว่าสำเร็จแต่ข้อมูลยังซ้ำอยู่จริง)

### 1.9 "ล้นสต็อก" บังของประกาศขอรับบริจาคที่เปิดอยู่ ✅
ปัญหา: มีประกาศเปิดรับ (0/10) แต่หน้าเว็บประชาชนขึ้นสถานะ "ล้นสต็อก" ปิดปุ่มบริจาค
การแก้ไข: กำหนดให้สถานะรับบริจาคได้บนหน้าเว็บประชาชน ดึงจาก "มีประกาศเปิดอยู่หรือไม่" เป็นหลัก ไม่ใช่สถานะสต็อกอัตโนมัติ

### 1.10 คำสั่ง EOC ติดป้าย "EOC" ผิดศูนย์ ✅
แก้ไขให้ป้ายชื่อศูนย์อ้างอิงตามศูนย์ผู้สร้างประกาศจริง (ตามกฎ A7 — ห้ามติดป้าย EOC บนคำสั่งที่ไม่ใช่คำสั่งข้ามศูนย์จริง)

### 1.11 เพิ่มฟีเจอร์เปิด/ปิดรับบริจาคระดับศูนย์ ✅
เพิ่ม toggle ควบคุมว่าศูนย์จะแสดงผลบน Public Needs Board หรือไม่

## 2. ระบบเว็บสาธารณะสำหรับประชาชน (Public Donor Website)

### 2.1 ยกเครื่องหน้าแรก/บอร์ดขอรับบริจาคทั้งหมด ✅
ทำ mockup ก่อนแล้วค่อยส่ง prompt: จัดเรียงการ์ดตามความเร่งด่วน (วิกฤต→สำคัญ→ปกติ→ไม่มีความต้องการไว้ท้ายสุด), การ์ดสูงเท่ากันด้วย flexbox, progress bar ย่อยใต้รายการเด่น, badge "+N รายการอื่น", ปุ่ม/ข้อความนุ่มลงสำหรับศูนย์ที่ไม่มีความต้องการ, ตัด step-indicator 4 ขั้นตอนออกจากหน้าเรียกดู (ให้เริ่มโชว์จาก Step 2), responsive มือถือ

### 2.2 หน้ารายละเอียดศูนย์ (คลิกเข้าไปดูรายการทั้งหมด) ✅
เพิ่มหน้าใหม่แยกสำหรับดูของที่ต้องการทั้งหมดของศูนย์นั้นๆ

### 2.3 ปุ่ม "+ ดูรายละเอียด" ไม่ทำงาน ✅
พบเป็นลิงก์ตาย แก้พร้อมกับการยกเครื่องข้อ 2.1

### 2.4 เอกภาพระดับความเร่งด่วน (Urgency Level) ✅
ปัญหา: แต่ละฟอร์ม/หน้าใช้คำไม่ตรงกัน ("ปกติ/สำคัญ/วิกฤต" vs "เร่งด่วนที่สุด/สูง/ปกติ")
แก้ไข: กำหนดมาตรฐานเดียว "วิกฤต (Critical) / สำคัญ (High) / ปกติ (Normal)" ใช้ทุกฟอร์ม/badge/ตัวกรอง ขยายตัวกรองฝั่งประชาชนจาก 2 ปุ่มเป็น 4 ปุ่ม (ทั้งหมด/วิกฤต/สำคัญ/ปกติ)

### 2.5 ตัดฟีเจอร์ใบเสร็จลดหย่อนภาษี (E-Donation) ✅
ตัดออกทั้งหมดตามที่ระบบไม่ต้องการฟีเจอร์นี้

### 2.6 ฟิลด์ Step 3 (นัดหมาย/โลจิสติกส์) แบบมีเงื่อนไข ✅
ตามวิธีนำส่งที่เลือก แสดงฟิลด์ต่างกัน: "นำมาส่งเอง" → ประเภทยานพาหนะ, "ส่งพัสดุ" → เลข Tracking, "ให้รถศูนย์ไปรับ" → ที่อยู่/จุดนัดรับของ (label เปลี่ยนจาก "ส่งของ" เป็น "รับของ")

### 2.7 ล็อกฟิลด์ "เลือกศูนย์รับบริจาค" ✅
ทำให้เป็น read-only เพราะถูกกำหนดไว้แล้วตั้งแต่เลือกการ์ดศูนย์ตอนต้น

### 2.8 หน้า "ตรวจสอบสถานะการบริจาคของฉัน" (ไม่ต้อง login) ✅
สร้างใหม่: ค้นหาด้วย Ref ID + เบอร์โทร (ต้อง match แบบ exact เพื่อกันดูข้อมูลคนอื่น) แสดงสถานะ/รายการ/เหตุผลปฏิเสธ/ปลายทางที่ส่งต่อ

### 2.9 รวมเมนู "บริจาคและจองคิว" + "ตรวจสอบสถานะบริจาค" เป็นเมนูเดียว ✅
เปลี่ยนเป็นปุ่ม "บริจาค" เดียว พร้อม hover-dropdown (รองรับแตะบนมือถือด้วย)

### 2.10 หน้ายืนยันตั๋วบริจาค (Step 4) ไม่บอกวิธีติดตามสถานะ ✅
เพิ่มกล่อง "วิธีติดตามสถานะการบริจาค" แสดง Ref ID + เบอร์โทรที่ใช้ลงทะเบียน ปุ่ม "คัดลอกรหัส" และปุ่มลัดไปหน้าตรวจสอบสถานะ

### 2.11 เชื่อมข้อมูลจากหน้ายืนยันตั๋ว → หน้าตรวจสอบสถานะ ✅
สั่งแก้ให้ Ref ID + เบอร์โทรถูกเติมอัตโนมัติเมื่อกดปุ่มไปหน้าตรวจสอบสถานะ (ไม่ต้องพิมพ์ซ้ำ) และให้หน้าตรวจสอบสถานะแสดง QR Code + ปุ่มโหลดเก็บได้ทันทีที่สถานะเปลี่ยนเป็นอนุมัติแล้ว — ยืนยันโดยผู้ใช้ 23 ก.ค.

## 3. ระบบจัดการคำร้องเบิกจ่าย (Tickets / โอนย้ายข้ามศูนย์)

### 3.1 ยกเครื่องหน้ารายละเอียด Ticket ทั้งหมด ✅
ทำ mockup การ์ดรวมต่อรายการก่อนส่ง prompt: รวมตาราง "Instruction Manifest" กับตารางแบ่งยอด/จัดเก็บที่เคยแยกกันให้เป็นการ์ดเดียวต่อ 1 สินค้า, แก้เลขล็อตที่ถูกตัดข้อความจนอ่านไม่ครบ, เปลี่ยนหัวข้อศัพท์ทหาร/ราชการ (MISSION OBJECTIVE DETAILS, INSTRUCTION MANIFEST ฯลฯ) เป็นภาษาธรรมดา, เพิ่มคำอธิบายใต้ปุ่ม "+ แบ่งจากอีกล็อต/โซน"

### 3.2 แก้ spacing ตารางที่แน่นเกินไป + แยก UI ตามทิศทาง Inbound/Outbound ✅
- เบิกออก (ต้นทางคือเรา): เปลี่ยนเป็นเลือก Lot จากของที่มีอยู่จริง (search-select) ระบบดึงโซน/วันหมดอายุมาแสดง read-only อัตโนมัติ กรอกแค่จำนวนที่จะเบิก
- รับเข้า (ปลายทางคือเรา): สร้าง Lot ใหม่อัตโนมัติตามเลขของศูนย์เราเอง พร้อมช่อง "อ้างอิง Lot ต้นทาง" (read-only) เพื่อสอบย้อนกลับ, วันหมดอายุดึงจากต้นทางมาให้ล่วงหน้าแต่ยังแก้ไขได้

### 3.3 Validation ก่อนกดอนุมัติจ่ายออก + Undo การลบแถว ✅
- ปุ่ม "อนุมัติจ่ายและนำสิ่งของออกส่ง" ต้อง disable จนกว่าจะเลือก Lot+จำนวนครบทุกรายการ และกรอกชื่อผู้ขับขี่/ทะเบียนรถแล้ว พร้อมข้อความแจ้งเหตุผลถ้ายังกดไม่ได้
- ไอคอนถังขยะลบแถว "แหล่งที่มา" เปลี่ยนจากลบทันทีเป็นมี Undo toast ค้าง 5 วินาที

### 3.4 บั๊ก Cross-shelter leak ในตารางรายการ Ticket ✅
ปัญหา: เลือกศูนย์ A ใน context บนสุด แต่ตารางกลับโชว์ Ticket ที่ไม่เกี่ยวกับศูนย์ A เลยสักแถว (บั๊กเดียวกับที่เคยเจอใน Pending Review Board)
สั่งแก้: กรองตามศูนย์ที่เลือกจริง, รวมคอลัมน์ซ้ำซ้อน, เปลี่ยนชื่อ "เวลาตอบรับ" ให้ชัดเจน, เพิ่ม legend อธิบายสถานะ, เพิ่ม banner เส้นทางต้นทาง→ปลายทางในหน้ารายละเอียดพร้อมระบุว่าศูนย์นี้เป็นฝั่งไหน — ยืนยันโดยผู้ใช้ 23 ก.ค.

## 4. ระบบแจกจ่ายสิ่งของ (Item Distribution)

### 4.1 ตัดสินใจสถาปัตยกรรม: แจกจ่ายแบบ 2 ขั้นตอน ✅
เทียบ "ตัดสต็อกตรงตอนสแกน" กับ "เบิกออกมาตั้งจุดแจกจ่ายก่อนแล้วค่อยแจก" — เลือกแบบ 2 ขั้นตอน เพราะมีจุดตรวจสอบความรับผิดชอบ (accountability) ระหว่างคลังกับหน้างาน และใช้สถาปัตยกรรม Ticket เดิมได้เลย

### 4.2 ออกแบบการสร้าง Ticket เบิกเพื่อแจกจ่ายหน้างานได้ 2 ทาง ✅
- ฝั่งหน้างาน "ขอเบิก" (Request) — สร้างคำขอ ยังไม่ตัดสต็อก
- ฝั่งคลัง "อนุมัติ+จัดชุด" (Approve & Prepare) — เลือก Lot จริง กดอนุมัติ ตัดสต็อกจริง สร้าง Active Batch
- ฝั่งคลังสร้างชุดแจกจ่ายเองโดยตรงได้ด้วย (ไม่ต้องรอคำขอ) สำหรับแผนแจกจ่ายล่วงหน้า

### 4.3 แก้ฟอร์ม "ขอเบิกพัสดุ" และ "จัดชุดแจกจ่ายโดยตรง" ให้ใช้งานได้จริง ✅
ปัญหาที่พบหลัง implement รอบแรก: เลือกสินค้าได้แค่รายการเดียว, หน่วยนับล็อกตายตัว, ไม่มี search-select, ฟอร์มฝั่งคลังไม่มีช่องจำนวน/เลือก Lot/ยอดคงเหลือเลย
สั่งแก้: เพิ่มรายการแบบหลายแถว (+เพิ่มรายการ), search-select ทุกจุดเลือกสินค้า/Lot, หน่วยนับดึงตามสินค้าจริง, ฝั่งคลังต้องมี Lot select + Split Allocation เหมือน Ticket โอนย้ายข้ามศูนย์, ตรวจสอบการเชื่อมข้อมูลคำขอจากหน้างาน→รายการรออนุมัติฝั่งคลัง — ยืนยันโดยผู้ใช้ 23 ก.ค.

## 11.4 Task #57 — แก้ 5 จุดในหน้า "จัดการพัสดุ" (แผงควบคุมสต็อก) 🟡

ทดสอบหน้า "แผงควบคุมสต็อก" → "จัดการพัสดุ: แก๊สหุงต้ม (ถังเตาปิกนิก 4kg)" พบ 5 จุด:
1. **สถานะควบคุมอายุ** ขึ้น "ปกติ" สีเขียวทั้งที่ล็อตไม่มีวันหมดอายุเลย (Exp. Date = "-") ทำให้เข้าใจผิดว่าเช็คแล้วโอเค ทั้งที่จริงคือไม่มีข้อมูลให้เช็ค ควรแยกเป็นป้ายเทา "ไม่มีวันหมดอายุ / N/A"
2. แถว **"Lot-001"** ในตาราง (0kg, ไม่มีโซนจัดเก็บ, ไม่มีวันหมดอายุ) ดูเหมือนข้อมูลหลอก/เทมเพลตค้าง ไม่ใช่ล็อตจริง ต้องเช็คและลบถ้าไม่ใช่ของจริง
3. ช่อง **"จำนวนที่ทำรายการ"** ในฟอร์มรับเข้าคลัง prefill ค่า "10" มาให้ ควรเป็นช่องว่างเปล่า
4. ดรอปดาวน์ **"แหล่งที่มา/หมวดหมู่"** ต้องเช็คว่าไม่มีตัวเลือก "จัดซื้อ" (ระบบไม่มี PO ตามกฎ A6) ควรมีแค่ "บริจาค" กับ "โอนย้ายจากศูนย์อื่น"
5. ช่อง **"เลขล็อต (Lot Number)"** ต้องเปลี่ยนจากพิมพ์ได้อิสระ+ปุ่ม Auto แยกต่างหาก เป็น **read-only auto-generate เสมอ** ตามฟอร์แมต `L-SH[index-shelter]-DDMMYYYY-XXXX` ห้ามพิมพ์เอง กันเลขล็อตชนกันจนข้อมูล 2 ล็อตที่เป็นของจริงคนละก้อนไปปนกัน

## 11.5 Task #56 — เชื่อม Purpose dropdown ในฟอร์ม "เบิกออก" (แผงควบคุมสต็อก) เข้ากับ Ticket จริง 🟡

หน้า "แผงควบคุมสต็อก" → "จัดการพัสดุ" (รายตัวสินค้า) → "ปรับปรุงยอดคงคลัง" → ปุ่ม "เบิกออก" มีดรอปดาวน์ "วัตถุประสงค์ (Purpose)": ส่งเข้าครัวกลาง / แจกจ่ายรายบุคคล (สแกน QR) / โอนย้ายไปศูนย์อื่น

**ปัญหาที่พบ**: ตอนนี้เลือก "โอนย้ายไปศูนย์อื่น" แล้วแค่ตัดสต็อกออกจากศูนย์เราพร้อมบันทึกเป็นข้อความ purpose เฉยๆ ไม่ได้ผูกกับระบบ Ticket ("จัดการคำร้องเบิกจ่าย") ที่สร้างไว้แล้วในหมวด 3 — ทำให้ศูนย์ปลายทางไม่มีอะไรมาแจ้งให้กดรับของเข้า ยอดหายไปโดยไม่มีการอ้างอิงถึงกัน (ขัดหลัก Ticket = Single Source of Truth ที่วางไว้ตลอดทั้งระบบ)

**การตัดสินใจของผู้ใช้**: เลือกแนวทาง "เชื่อมเข้า Ticket จริง" — เก็บตัวเลือกในดรอปดาวน์ไว้เหมือนเดิม แต่พอเลือก "โอนย้ายไปศูนย์อื่น" ต้องบังคับเลือกศูนย์ปลายทางเพิ่ม แล้วระบบทำงาน 2 อย่างพร้อมกัน: (1) ตัดสต็อกจากล็อตที่เลือกจริง (2) สร้าง Ticket โอนย้ายให้อัตโนมัติ (ใช้สถาปัตยกรรม Ticket เดิมในหมวด 3.2) เพื่อให้ศูนย์ปลายทางเห็นรายการรอรับเข้าคลังตามระบบที่มีอยู่แล้ว

ส่ง prompt แก้แล้ว 24 ก.ค. รอผลทดสอบ
