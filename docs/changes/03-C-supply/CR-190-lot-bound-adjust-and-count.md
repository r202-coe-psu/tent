# CR-190 — ปรับยอด / ตรวจนับ ผูกกับล็อต

> **สรุป (TL;DR):**
>
> - การปรับยอดและการตรวจนับต้องอ่านยอดรายล็อตจาก projection เดียวกับตารางสต็อก (`projectStockLotBalances`) และ
>   **การตัดยอด** (`adjust` ติดลบ ทั้งจากฟอร์มปรับยอดและ `count_mismatch` จากตรวจนับ) ต้องอ้างล็อตที่ตัดด้วย `lot_ref`
> - **ยอดที่เพิ่ม** (ปรับเพิ่ม / ตรวจนับเกิน) เป็นล็อตใหม่เสมอ (`lot_ref = _id` ของตัวเอง) ไม่บวกเข้าล็อตเดิม
>   — ข้อยกเว้น: `distribution_return` (ของเหลือคืนจากตั๋ว/batch) เป็นแถวบวกที่อ้าง `lot_ref` ของ lot ต้นทาง ([CR-208](CR-208-lot-return-warehouse.md) §5)
> - ตอนบันทึก การตัดยอดที่อ้างล็อตต้อง**พอในล็อตนั้น** ไม่ใช่แค่พอในยอดรวมทั้งสินค้า · ไม่เปลี่ยน field / ไม่ bump `schema_v`

---

## Why

- ฟอร์มปรับยอดและตรวจนับเดิมรวมยอดจากฟิลด์ `lot` (ที่เก็บ + วันหมดอายุ) ของแต่ละแถว แต่ตารางสต็อกตัดล็อตตาม `lot_ref`
  แถวปล่อยรถที่มีแค่ `lot_ref` จึงไม่ถูกนับ: ฟอร์มแสดง 1200 ขณะที่ตารางแสดง 1199 และตรวจนับที่กรอก 1199 บันทึก
  `count_mismatch` −1 ซ้ำ (#569)
- เมื่อแถวตัดยอดเริ่มอ้าง `lot_ref` การตรวจยอดตอนบันทึกที่ดูแค่ยอดรวมทั้งสินค้าจะปล่อยให้ตัดเกินล็อตได้ (ล็อต A=5, B=100 →
  ตัด A 10 ก็ผ่าน) แล้ว replay ล็อตพังถาวร เพราะ ledger เป็น append-only (review PR #775)

## Change

| | ก่อน | หลัง |
| --- | --- | --- |
| ยอดรายล็อตในฟอร์มปรับยอด / ตรวจนับ | รวมจาก `lot` ของแต่ละแถว | `projectStockLotBalances` (เท่ากับตารางสต็อก) |
| แถว `adjust` ติดลบ (ปรับลด / `count_mismatch` ขาด) | ไม่มี `lot_ref` | `lot_ref` = ล็อตที่ตัด |
| แถว `adjust` บวก (ปรับเพิ่ม / ตรวจนับเกิน) | ไม่มี `lot_ref` | ล็อตใหม่ `lot_ref = _id` (ห้ามอ้างล็อตเดิม) |
| ตรวจยอดก่อนบันทึก | ยอดรวมทั้งสินค้า | แถวที่อ้างล็อต: ยอดของล็อตนั้น ณ ตอนบันทึก |
| ปลายทางการเบิกใน `lot.note` ของแถวขาออก | กลายเป็น "ที่เก็บ" ในตัวกรอง / ฟอร์ม | ไม่ใช่ที่เก็บ (ล็อตมาจากแถวรับเข้าเท่านั้น) |

**Requirements**

- FR-1 — ฟอร์มปรับยอด ตรวจนับ และตารางสต็อกต้องได้ยอดรายล็อตจาก `projectStockLotBalances` (project ทีละสินค้า)
- FR-2 — แถว `adjust` ที่ `qty < 0` ที่ฟอร์มปรับยอดหรือตรวจนับเขียน ต้องมี `lot_ref` ของล็อตที่ตัด
- FR-3 — `adjustInputSchema` รับ `lot_ref` เฉพาะการปรับลด; การปรับเพิ่มที่มี `lot_ref` ต้องถูกปฏิเสธ — ยอดเพิ่มเป็นล็อตใหม่
  (`createParsedStockLedger` บังคับ `lot_ref === _id` อยู่แล้ว) โดยคงที่เก็บ / วันหมดอายุของล็อตที่เลือก
- FR-4 — ก่อนบันทึก แถวตัดยอดที่อ้างล็อตต้องผ่าน: ล็อตมีอยู่ใน projection ล่าสุด, `item_id` / `unit` ตรงกัน และ
  ยอดของล็อต ≥ ผลรวมที่ตัดจากล็อตนั้นในคำขอเดียวกัน; ไม่ผ่าน → ไม่เขียนแถวใดเลย พร้อมข้อความภาษาไทย
- FR-5 — แถวตัดยอดที่ไม่อ้างล็อต (caller เก่า) ยังตรวจกับยอดรวมทั้งสินค้าเหมือนเดิม และ replay แบบ FEFO→FIFO เดิม
- FR-6 — ล็อตติดลบไม่ใช่ประวัติที่ replay ไม่ได้ — ตารางสต็อกและตรวจนับแสดงสินค้าและล็อตนั้นพร้อมยอดติดลบและคำเตือน
  ([CR-216](CR-216-negative-stock-lots.md) FR-6/FR-7). สินค้าที่ประวัติเสียตาม CR-216 FR-4 (`StockLotIntegrityError`) ยังข้ามเฉพาะสินค้านั้น
  และแจ้งชื่อให้ติดต่อผู้ดูแลระบบ (ตารางสต็อก, ตรวจนับ) หรือแจ้งในฟอร์มปรับยอด
- FR-7 — ล็อตที่เลือกในฟอร์มปรับยอดแล้วยอดเหลือ 0 ระหว่างกรอก → ไม่บันทึก ให้เลือกล็อตใหม่
- FR-8 — ตัวกรองที่เก็บในตารางสต็อกมาจากล็อตที่ยังมียอด ไม่ใช่จากทุกแถว ledger

## Acceptance

- ledger รับเข้า +1200 (มี `lot`) + ปล่อยรถ −1 (มีแค่ `lot_ref`): ฟอร์มปรับยอด ตรวจนับ และตารางสต็อกได้ 1199 เท่ากัน
- ตรวจนับกรอก 1199 บนล็อตนั้น → ไม่มีแถว `count_mismatch`
- ปรับลด 9 จากล็อต → แถว `adjust` มี `lot_ref` ของล็อตนั้น; ปรับเพิ่ม 6 → แถวใหม่ไม่อ้างล็อตเดิม และคงวันหมดอายุของล็อต
- ล็อต A=5, B=100 แล้ว A ถูกตัดหมดระหว่างเปิดฟอร์ม → ตัด A อีก 5 ถูกปฏิเสธ แม้ยอดรวม 100 ≥ 5 (ทั้งปรับยอดและตรวจนับ)
- แถว `distribute` ที่มีปลายทางใน `lot.note` ไม่สร้างที่เก็บใหม่ในตัวกรอง ฟอร์มปรับยอด หรือกลุ่มตรวจนับ

## Impact

- **ข้อมูลเดิม:** ไม่ต้อง migrate — แถว `adjust` เก่าที่ไม่มี `lot_ref` ยัง replay แบบ FEFO→FIFO (FR-5)
- **VDU (`_design/access`):** ไม่เปลี่ยน — การตรวจตาม FR-4 อยู่ฝั่ง client/repository เหมือนการตรวจยอดรวมเดิม
- **ความพร้อมกัน:** การตรวจตาม FR-4 อ่าน ledger ล่าสุดก่อนเขียน แต่ยังไม่จองล็อตแบบ reservation claim ของการเบิกจ่าย
  (`stock_lot_reservation`) — คำขอสองคำขอที่ตัดล็อตเดียวกันพร้อมกันในเสี้ยววินาทียังผ่านได้ทั้งคู่ — ยอมรับตาม #881 ทาง D:
  ล็อตที่ติดลบแสดงพร้อมคำเตือนและแก้ด้วยการปรับยอด ([CR-216](CR-216-negative-stock-lots.md))
- **schema_v:** ไม่ bump
