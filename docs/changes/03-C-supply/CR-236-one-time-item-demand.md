# CR-236 — ความต้องการของแจกครั้งเดียวเทียบกับของพร้อมแจก

> **สรุป (TL;DR):**
>
> - **เปลี่ยนอะไร:** เพิ่มกติกาคำนวณ "ต้องการ / มีพร้อมแจก / ขาด / coverage / สถานะ" ต่อสินค้า `item_master.distribution_type = one_time` ที่ active ในศูนย์
> - **เพื่อใคร:** ผู้เข้าหน้า supply (`requireWarehouseAccess`) ของศูนย์ตนเอง — ใช้ดูว่าของแจกครั้งเดียวในคลังพอสำหรับคนในศูนย์หรือไม่
> - **Dev ต้อง build:** ฟังก์ชัน domain แบบ pure + แท็บ "ของแจกครั้งเดียว" ใน `/back-office/supply`
> - **กระทบ:** ไม่มี field ใหม่ ไม่ bump `schema_v` ไม่แตะ worker; ใช้ฐานคนตาม [CR-223](CR-223-shelter-people-base-for-stock.md)

---

## 1. Requirements

กติกาคำนวณ (ต่อสินค้า `one_time` ที่ไม่ถูก deactivate และไม่ถูก merge):

| ID    | ค่า                     | นิยาม                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| ----- | ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| FR-1  | **คนในศูนย์**           | ผลของ `countShelterPeople` (ฐานเดียวกับอาหารตาม CR-223: ผู้พักพิงในศูนย์ + staff + volunteer **ที่ check-in อยู่ในศูนย์นี้**) นับ ณ ขณะนี้                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| FR-2  | **ต้องการ**             | `(คนในศูนย์ − รับแล้ว) × qty_per_person` (รับแล้ว ตาม FR-16). ถ้าสินค้าไม่ได้ตั้ง `qty_per_person` **หรือตั้งเป็น 0** ให้ใช้ **1** และติดป้าย "ยังไม่ตั้งจำนวนต่อคน" (`qtyPerPersonMissing = true`)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| FR-3  | **มีพร้อมแจก**          | `max(0, Σ คงเหลือ lot ที่ใช้ได้ − ยอดจอง)`. **lot ที่ใช้ได้** = ยังไม่หมดอายุตามกติกาเดียวกับหน้าคลัง (`isLotExpired(lot, now, item)` จาก barrel `$lib/features/operations` — ต้องส่ง `item` เพื่อใช้กติกา `shelf_life_days`: `now >= expiryInstant(lot.expiry)` ตาม CR-195; ไม่มี expiry ให้ดู `shelf_life_days`) และคงเหลือ > 0 — lot ติดลบ (CR-216) ตัดออกทั้ง lot ไม่นำมาหักยอด lot อื่น. **ยอดจอง** = ผลรวม `pending_claims[].qty` ของ `stock_lot_reservation` ของ lot ที่ใช้ได้ (claim ที่ commit แล้วอยู่ใน `stock_ledger` `distribute` และสะท้อนในคงเหลือแล้ว ห้ามหักซ้ำ)                                                                                                                                                               |
| FR-4  | **ขาด (ต้องหาเพิ่ม)**   | `max(0, ต้องการ − มีพร้อมแจก)` — หน้าจอเรียกว่า "ต้องหาเพิ่ม" และต้องการคือ "ต้องแจกอีก" (หักผู้ที่รับแล้วตาม FR-2 แล้ว)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| FR-5  | **ครอบคลุม (coverage)** | `มีพร้อมแจก ÷ ต้องการ` แสดงเป็น % **ทศนิยม 1 ตำแหน่ง** (ปัดครึ่งขึ้น แต่แถวที่ยังขาดห้ามแสดง 100% — ไม่เกิน 99.9%) พร้อมแถบ progress (สีเขียว = พอ, เหลือง = ≥ 50%, แดง = < 50%); ถ้า `ต้องการ = 0` ให้แสดง `—`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| FR-6  | **สถานะ**               | 3 ระดับตามสัดส่วน `มีพร้อมแจก ÷ ต้องการ`: **พอแจก** (เขียว) เมื่อ `มีพร้อมแจก ≥ ต้องการ` (รวมกรณี `ต้องการ = 0`); **แจกได้บางส่วน** (เหลือง) เมื่อ `มีพร้อมแจก ≥ 50% ของต้องการ` แต่ยังไม่พอ; **ขาดแคลน** (แดง) เมื่อต่ำกว่า 50%. เส้นแบ่ง 50% ใช้ตัดสินจากค่าจริง ไม่ใช่เลขที่ปัดแล้ว                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| FR-7  | หักผู้รับแล้ว           | ความต้องการ **หัก** คนที่ได้รับสินค้านี้ไปแล้วตาม FR-16 (เดิม: ไม่หัก — เปลี่ยนใน amendment 2026-11-07); ตารางแสดงจำนวนผู้รับแล้วต่อสินค้า                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| FR-8  | ชนิดตัวเลข              | ทุกค่าใช้ `base_unit` ของสินค้า และคำนวณด้วย qty_str / Decimal ตามแนวที่ใช้กับ stock อยู่แล้ว **ห้ามใช้ float**. `qty_per_person` ในโค้ด catalog เป็น `number` (schema ระบุ `qty_str`) — แปลงเป็น Decimal จาก `String(value)` ที่ขอบ input ของฟังก์ชัน domain ก่อนคูณ                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| FR-9  | ขอบเขตสินค้า            | รวมเฉพาะ `distribution_type = one_time` ที่ `deactivated` ไม่เป็น true และไม่มี `merged_into`; `recurring`, สินค้าที่ **ไม่มี** `distribution_type` และอาหารไม่รวม (อาหารอยู่ในแท็บวิเคราะห์เสบียงอาหารแล้ว)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| FR-16 | **รับแล้ว**             | จำนวนคนในศูนย์ที่เคยรับสินค้านี้แล้ว นับ distinct คนจาก `distribution_log` ของ `item_id` นั้น ที่ `recipient_type` เป็น `evacuee`, `volunteer` หรือ `staff`, `recipient_id` ไม่ว่าง และ `status` **ไม่ใช่ `voided`** (`fulfilled`, `active`, `partially_returned`, `returned`, `lost`, `waived` นับว่ารับแล้ว). นับเฉพาะคนที่อยู่ในฐาน FR-1 ตอนนี้: ผู้พักพิงที่ยังอยู่ (`evacuee:*`), จิตอาสาที่เช็กอินในศูนย์นี้ (`volunteer:*`), เจ้าหน้าที่ของศูนย์ (`user:*`); คนที่ย้ายออก/เช็กเอาต์และผู้รับ `outside` ไม่นับ; จิตอาสาที่เป็นบัญชีเจ้าหน้าที่ด้วยนับเป็นคนเดียวไม่ว่าบันทึกด้วย id แบบไหน; ค่าไม่เกินจำนวนคนในศูนย์; **ไม่อัปเดตสดเมื่อมีการแจก** (อ่านตอนเปิดแท็บหรือเมื่อข้อมูลเก่าเกิน stale time) ผู้ใช้โหลดหน้าใหม่เพื่อดูค่าล่าสุด |
| FR-19 | **อยู่ที่จุดแจก**       | จำนวนชิ้นที่เบิกไปจุดแจกแล้วแต่ยังไม่ได้แจกให้ใคร ต่อสินค้า = `Σ −qty` ของ `stock_ledger` `distribute` ที่ `ref_id` ขึ้นต้น `requisition_ticket:` − `Σ qty` ของ `distribution_return` − (`Σ qty` − `Σ qty_returned`) ของ `distribution_log` ที่ไม่ `voided` (ทุกประเภทผู้รับ รวม `outside`); ขั้นต่ำ 0; `distribute` ที่ `ref_id` เป็น `distribution_batch:` (แจกตรง) และ reason อื่นไม่นับ. ชิ้นเหล่านี้ **นับเป็นของที่มี** เมื่อเทียบกับความต้องการ: `ขาด = max(0, ต้องการ − (มีพร้อมแจก + อยู่ที่จุดแจก))`, coverage และสถานะ (FR-5, FR-6) ใช้ `มีพร้อมแจก + อยู่ที่จุดแจก`; คอลัมน์ "มีพร้อมแจก" ยังเป็นของในคลังอย่างเดียว และแสดงบรรทัดย่อย "+N อยู่ที่จุดแจก" เมื่อมากกว่า 0                                                            |

## 2. Acceptance

ใช้ `now` คงที่ และค่าคาดหวังคำนวณมือในทุกเทสต์

- **AC-1** 120 คน × `qty_per_person` 1, มี 100 → ต้องการ 120 / ขาด 20 / coverage 83% / `แจกได้บางส่วน`
- **AC-2** `qty_per_person` 2, มี 300 → ต้องการ 240 / ขาด 0 / `พอแจก`
- **AC-3** ไม่มี `qty_per_person` หรือเป็น 0 → ใช้ 1 และ `qtyPerPersonMissing = true`
- **AC-4** lot ที่หมดอายุตาม `isLotExpired` (ส่ง `item`) (รวม date-only ถึงสิ้นวันเวลาไทย และ `shelf_life_days` เมื่อไม่มี expiry) ไม่ถูกนับเป็นของพร้อมแจก
- **AC-5** ผลรวม `pending_claims[].qty` ถูกหักออก และ "มีพร้อมแจก" ไม่ติดลบ
- **AC-5a** lot ติดลบไม่ถูกนับ และไม่ลดยอดของ lot อื่น (เช่น lot A 50, lot B −10 → มีพร้อมแจก 50)
- **AC-6** คนในศูนย์ = 0 → ต้องการ 0, coverage `—`, สถานะ `พอแจก`
- **AC-7** สินค้า `recurring`, ไม่มี `distribution_type`, deactivated และ merged ไม่ถูกรวม
- **AC-8** ตัวเรียง: แถวที่ยังไม่พอแจกขึ้นก่อน ตามด้วย coverage น้อยไปมาก
- **AC-9** แท็บแสดงทุกสินค้า `one_time` ที่ active; สินค้าที่ไม่ตั้ง `qty_per_person` มีป้ายเตือน; ใช้งานบน mobile ได้
- **AC-10** 120 คน, รับแล้ว 30, มี 50 → ต้องแจกอีก 90 / ต้องหาเพิ่ม 40 / `แจกได้บางส่วน`
- **AC-11** รับแล้วมากกว่าคนในศูนย์ → ถือว่ารับแล้ว = คนในศูนย์ (ต้องแจกอีก 0); `voided`, ผู้รับ `outside` และผู้รับที่ย้ายออก/เช็กเอาต์ไม่ถูกนับ; คนเดียวกันที่มีหลาย log นับครั้งเดียว
- **AC-14** เจ้าหน้าที่ (`user:*`) และจิตอาสา (`volunteer:*`) ที่รับสินค้าและยังอยู่ในศูนย์ถูกนับเป็นรับแล้ว; จิตอาสาที่เป็นบัญชีเจ้าหน้าที่ด้วย นับเป็นหนึ่งคน
- **AC-15** คนในศูนย์ 316, รับแล้ว 1, มี 100 ในคลัง, เบิกไปจุดแจก 100 และแจกบันทึกแล้ว 1 → อยู่ที่จุดแจก 99; ต้องแจกอีก 315 / ขาด 116 (ไม่ใช่ 215); เบิกครบและแจกครบ → ไม่มีรายการ "อยู่ที่จุดแจก"
- **AC-13** สถานะ 3 ระดับ: มี 100 / ต้องการ 100 → พอแจก; 99 และ 50 → แจกได้บางส่วน; 49 และ 0 → ขาดแคลน; ต้องการ 0 → พอแจก
- **AC-12** แถวที่ขาดไม่แสดง `100%` (เช่น 997/1000 → `99.7%`; 99.97% → `99.9%`); 200/316 → `63.3%`

## 3. Spec delta

- `docs/data/schema.md` — **ไม่เปลี่ยน**: `item_master.distribution_type` (§ catalog) และ `qty_per_person` มีอยู่แล้ว ค่าคำนวณไม่ persist
- ไม่มีเอกสาร feature/data อื่นที่นิยามความต้องการของแจกครั้งเดียว — CR นี้เป็นที่บันทึกกติกาเพียงแห่งเดียว

## 4. Impact

- **Code:** ฟังก์ชัน pure ใน `sop-ratios/domain/` (รับ item master, จำนวนคน, lot balances, reservations เป็น input ผ่าน barrel) + แท็บ UI + ตัวเรียงแถว
- **Tests:** unit ตาม AC-1..AC-8 (ค่าคำนวณมือ, `now` คงที่) + sort helper
- **Worker / projection:** ไม่เปลี่ยน ไม่ bump `PROJECTION_VERSION`
- **CouchDB `_design/*`:** ไม่เปลี่ยน — อ่านอย่างเดียว

## 5. Migration

ไม่มี — ค่าถูกคำนวณตอนอ่านทุกครั้ง ไม่มีเอกสารที่ persist และไม่มี `schema_v` เปลี่ยน

## 6. Out of scope

- ผู้ที่รับผ่าน `distribution_issue` (batch flow ที่ยังไม่มี UI เรียก)
- index ใหม่สำหรับค้น `distribution_log` ตาม `item_id` (ตอนนี้อ่านทั้ง type แล้วกรองฝั่ง client — รอตัดสินใจเรื่อง `docs/data/schema.md` §7)
- กติการะดับครัวเรือน (เช่น เต็นท์ต่อครอบครัว)
- buffer % (`calculateNfiTarget`) และการสร้างคำขอแจกอัตโนมัติ
- สินค้า `recurring` และอาหาร

## Why

- ของแจกครั้งเดียวไม่มี DoC (วันต่อวัน) จึงใช้แท็บวิเคราะห์เสบียงอาหารไม่ได้; ต้องมีตัวเลขเดียวที่ตอบว่า "ของพอสำหรับคนในศูนย์ตอนนี้ไหม"
- ใช้ฐานคนเดียวกับ CR-223 เพื่อให้หน้าครัว หน้าสต็อก และแท็บนี้ตรงกัน
- หักผู้รับแล้ว (amendment 2026-11-07): ของแจกครั้งเดียวที่แจกแล้วไม่ต้องแจกซ้ำ ถ้าไม่หักตัวเลข "ขาด" จะเกินจริง; นับจาก `distribution_log` ซึ่งเป็นที่ที่หน้างานแจกบันทึกจริง
