# CR-237 — หน้าคลังแสดงของที่กำลังมา

> **สรุป (TL;DR):**
>
> - **เปลี่ยนอะไร:** เพิ่มสวิตช์ "รวมของที่กำลังมา" ในหน้าคลัง (`stock-table`); เมื่อเปิด คอลัมน์ "คงเหลือ" แสดงยอดรวม (ในคลัง + กำลังมา), แท่งแบ่ง 2 ช่วง และวันที่ของจะมาถึง
> - **นิยาม "ของที่กำลังมา":** (1) รายการบริจาคที่ `approved` ในใบที่ยังไม่รับ (2) ใบโอนระหว่างศูนย์ที่ `shipped` เข้าศูนย์นี้
> - **Dev ต้อง build:** endpoint สรุป read-only `GET /api/back-office/stock/incoming`, ฟังก์ชัน domain แบบ pure, query ใน `features/operations`, UI สวิตช์/แท่ง/popover/แถบ "ยังไม่จับคู่"
> - **กระทบ:** ไม่มี field ใหม่ ไม่ bump `schema_v` ไม่แตะ worker/`_design/*`. สวิตช์เปลี่ยนแค่การแสดงผล — ความเร่งด่วน ป้ายสถานะ attention cards และการเรียงยังคิดจากของในคลังเท่านั้น

---

## 1. Requirements

### 1.1 นิยาม "ของที่กำลังมา"

| ID   | Requirement                                                                                                                                                                                                                                                                                                                                                                                             |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| FR-1 | **บริจาค** (`donation` ใน `shelter_{code}`): นับรายการที่ `review_status: approved` ของใบที่ `status` ยังไม่เป็น `received` / `rejected` / `expired` / `cancelled` / `redirected`. วันที่ที่ใช้ = `logistics.slot.date` ถ้ามี ไม่มีใช้ `logistics.eta`. **ใบก่อน schema_v 7** (รายการไม่มี `review_status`) ใช้สถานะระดับใบตาม CR-174 AC-8: นับทุกรายการของใบที่ `status: verifying`, ใบสถานะอื่นไม่นับ |
| FR-2 | **ใบโอน** (`stock_transfer` ใน `central_ops`): นับเมื่อ `status: shipped` และ `to_shelter` = ศูนย์นี้. วันที่ที่ใช้ = `timeline.shipped.at`                                                                                                                                                                                                                                                             |
| FR-3 | **ไม่นับ:** รายการบริจาคที่ `review_status` เป็น `pending` / `rejected` (แม้ใบจะยังไม่ปิด) และใบโอนที่ยัง `requested` / `disputed`                                                                                                                                                                                                                                                                      |
| FR-4 | จำนวนบริจาคแปลงเป็นหน่วยฐาน (`base_unit`) ด้วย `conversions[]` ของ `item_master` (`qtyToBaseUnit`). ใช้ qty_str / Decimal เท่านั้น ห้าม float                                                                                                                                                                                                                                                           |
| FR-5 | **ยังไม่จับคู่:** รายการ `free_text` (ไม่มี `item_id`) และรายการที่แปลงหน่วยไม่ได้ **ไม่**บวกเข้าแถวสินค้า — แสดงเป็นแถบสรุปด้านบน "กำลังมา N รายการ ยังไม่จับคู่สินค้า" พร้อมลิงก์ไปใบบริจาค                                                                                                                                                                                                           |
| FR-6 | **เลยกำหนด:** ใบบริจาคที่เลยวันนัด/ETA แล้วแต่ยังไม่ `expired` ยังนับ และติดป้าย "เลยกำหนด" (`overdue`)                                                                                                                                                                                                                                                                                                 |
| FR-7 | **ไม่นับซ้ำ:** ใบโอนที่ `shipped` แล้วไม่ถูกนับซ้ำในโหมดรวมทุกศูนย์ (SA) เพราะต้นทางลง `transfer_out` ใน ledger ตั้งแต่ตอนส่ง; ยอดกำลังมาของโหมดนี้ = ผลรวมของทุกศูนย์ ไม่ผ่านการหักลบกับ ledger                                                                                                                                                                                                        |

### 1.2 Endpoint สรุป

| ID    | Requirement                                                                                                                                                                                                                                                                                                    |
| ----- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| FR-8  | `GET /api/back-office/stock/incoming?shelter_code=` (Node BFF, read-only) คืนแถวต่อใบ: `source` (`donation` / `transfer`), `ref` (booking_ref / transfer id), `item_id`, `qty` (หน่วยฐาน, qty_str), `date`, `overdue` + รายการยังไม่จับคู่แยกออกมา. **ไม่ส่ง PII ผู้บริจาค** (ชื่อ, เบอร์, ที่อยู่, ทะเบียนรถ) |
| FR-9  | สิทธิ์: ผู้ที่ดูสต็อกของศูนย์นั้นได้ (หน้า supply ตาม `requireWarehouseAccess`) — **ไม่**ต้องผ่าน gate สิทธิ์บริจาค. ศูนย์อื่นที่ไม่ใช่ศูนย์ตน → ปฏิเสธ (ยกเว้น SA)                                                                                                                                            |
| FR-10 | SA โหมดทุกศูนย์: บริจาค fan-out ตาม `listShelterCodes()`; ใบโอน query `central_ops` ครั้งเดียวด้วย `status=shipped` (index `(type,status)`)                                                                                                                                                                    |
| FR-11 | ใบโอนศูนย์เดียว: กรอง `to_shelter` ฝั่ง server (index `(type,to_shelter,created_at)`) และแบ่งหน้าครบ — ห้ามติดเพดาน 50 ใบ                                                                                                                                                                                      |
| FR-12 | Client: TanStack query ใน `features/operations` ยิงเมื่อเปิดสวิตช์เท่านั้น; refetch เมื่อกลับมาที่แท็บ; invalidate หลังรับของบริจาค/รับโอนในแอป. **ไม่ทำ live `_changes`**                                                                                                                                     |

### 1.3 UI (หน้า supply, `requireWarehouseAccess`)

| ID    | Requirement                                                                                                                                                                                             |
| ----- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| FR-13 | สวิตช์ "รวมของที่กำลังมา" อยู่ข้าง "ทั้งแคตตาล็อก" ใน `stock-filters`; ค่าเริ่มต้น **ปิด**; เก็บค่าใน URL (`stock-url-state`). ปิดสวิตช์ = หน้าตาเหมือนเดิมทุกประการ                                    |
| FR-14 | เมื่อเปิด คอลัมน์ "คงเหลือ": ตัวเลข = ในคลัง + กำลังมา                                                                                                                                                  |
| FR-15 | แท่ง (`StockBar`): ช่วงในคลังใช้สีสถานะเดิม (แดง/เหลือง/เขียว คิดจาก **ในคลังอย่างเดียว** ตามเกณฑ์สั่งเพิ่ม) ต่อด้วยช่วงกำลังมาสีฟ้าลายทาง; ขีดเกณฑ์อยู่ที่เดิม                                         |
| FR-16 | ใต้แท่ง: "ในคลัง X · กำลังมา Y (เร็วสุด d MMM)". แตะ/hover แสดง popover รายการแต่ละใบ: แหล่ง (บริจาค/โอน), เลขใบ, วันที่, จำนวน, ป้ายเลยกำหนด, ลิงก์ไปหน้าใบ — แสดงลิงก์เฉพาะผู้ที่มีสิทธิ์เปิดหน้านั้น |
| FR-17 | สินค้าที่ไม่เคยรับเข้าแต่มีของกำลังมา แสดงแถว (ในคลัง 0) แม้ไม่ได้เปิด "ทั้งแคตตาล็อก"                                                                                                                  |
| FR-18 | กรองที่เก็บเฉพาะจุด (storage point) → สวิตช์ disabled พร้อมเหตุผล "ของที่กำลังมายังไม่มีที่เก็บ"                                                                                                        |
| FR-19 | ใช้คู่กับโหมด "แสดงยอดรวมทุกศูนย์" (SA) ได้; ยอดกำลังมา = ผลรวมทุกศูนย์ (FR-7, FR-10)                                                                                                                   |
| FR-20 | **ไม่เปลี่ยนตามสวิตช์:** การเรียง (เร่งด่วนก่อน / คงเหลือน้อยก่อน), ป้ายสถานะ, attention cards, การแจ้งเตือน — คิดจากของในคลังเท่านั้น                                                                  |
| FR-21 | มือถือ: `stock-card` ใช้ `StockBar` ตัวเดียวกัน พฤติกรรมเดียวกับตาราง                                                                                                                                   |

## 2. Acceptance

- **AC-1** สวิตช์ปิด (ค่าเริ่มต้น) → หน้าตา/ข้อมูลเหมือนก่อนมี CR; ค่าสวิตช์ persist ใน URL
- **AC-2** เปิดสวิตช์ → คงเหลือ = ในคลัง + กำลังมา; แท่ง 2 ช่วง; สีสถานะคิดจากในคลังอย่างเดียว (ตัวอย่าง: ในคลัง 0 + กำลังมา 100 ยังเป็นสีแดง)
- **AC-3** นับเฉพาะบริจาค `approved` ที่ใบยังไม่รับ และใบโอน `shipped` เข้าศูนย์นี้; `pending` / `requested` / `disputed` ไม่นับ ใบก่อน schema_v 7 ที่ไม่มี `review_status` นับทุกรายการเมื่อใบเป็น `verifying` (FR-1)
- **AC-4** บริจาคหน่วยอื่นแปลงด้วย `conversions[]`; `free_text` และหน่วยแปลงไม่ได้ไปอยู่ในแถบ "ยังไม่จับคู่" ไม่บวกเข้าแถวสินค้า
- **AC-5** ใบเลยวันนัด/ETA ที่ยังไม่ expired ยังนับและมีป้าย "เลยกำหนด"
- **AC-6** สินค้าไม่เคยรับเข้า + มีของกำลังมา → มีแถว (ในคลัง 0)
- **AC-7** กรองที่เก็บเฉพาะจุด → สวิตช์ disabled พร้อมเหตุผล
- **AC-8** โหมดรวมทุกศูนย์ (SA) + สวิตช์ → ยอดกำลังมาเป็นผลรวมทุกศูนย์ ใบโอน shipped ไม่นับซ้ำ
- **AC-9** การเรียง ป้ายสถานะ attention cards เหมือนเดิมไม่ว่าสวิตช์เปิด/ปิด
- **AC-10** `stock-card` มือถือทำงานเหมือนตาราง
- **AC-11** response ของ endpoint ไม่มี PII ผู้บริจาค; ศูนย์ที่มีใบโอน shipped > 50 ใบ ได้ครบ (ไม่ติดเพดาน)
- **AC-12** unit test domain (รวมยอด / แปลงหน่วย / ยังไม่จับคู่ / เลยกำหนด / ไม่นับ status ที่ไม่เข้าเงื่อนไข / ใบก่อน schema_v 7 ไม่มี `review_status`) + test ของ endpoint (สิทธิ์, ไม่มี PII, pagination)

## 3. Spec delta

- `docs/data/schema.md` — **ไม่เปลี่ยน**: ใช้ field ที่มีอยู่ (`donation.logistics.slot.date` / `logistics.eta`, `stock_transfer.status` / `to_shelter` / `timeline.shipped.at`, `item_master.conversions[]`). ค่าคำนวณไม่ persist
- ไม่มีเอกสาร feature/data อื่นนิยาม "ของที่กำลังมา" — CR นี้เป็นที่บันทึกนิยามเพียงแห่งเดียว

## 4. Impact

- **Code:** `operations` (domain ฟังก์ชัน pure + query + UI), route BFF ใหม่ `api/back-office/stock/incoming` (อ่านด้วย credential ฝั่ง server ตามแนวเดียวกับ route back-office เดิม; ไม่ส่ง PII)
- **Tests:** unit domain + endpoint ตาม AC-12
- **Worker / projection:** ไม่เปลี่ยน ไม่ bump `PROJECTION_VERSION`
- **CouchDB `_design/*`:** ไม่เปลี่ยน — ใช้ index `(type,status)` และ `(type,to_shelter,created_at)` ที่มีอยู่
- **Ops:** ไม่ต้อง redeploy `_design/*`

## 5. Migration

ไม่มี — ค่าถูกคำนวณตอนอ่านทุกครั้ง ไม่มีเอกสารที่ persist และไม่มี `schema_v` เปลี่ยน

## 6. Out of scope

- บั๊กหน่วยใน `transfer-form` / `donationShortfall` (แยกเป็น issue ใหม่)
- จับคู่ `item_id` ตั้งแต่ตอนอนุมัติบริจาค
- live update ด้วย `_changes`
- การแจ้งเตือน/ความเร่งด่วนที่คิดรวมของกำลังมา

## Why

- ผู้ใช้จากการอบรมระบบ (2026-11-03) ต้องเห็น "มีของเท่าไหร่ และกำลังจะมาอีกเท่าไหร่ เมื่อไหร่" ในหน้าคลังเอง ไม่ต้องไปเปิดใบบริจาค/ใบโอนทีละใบ
- สวิตช์ปิดเป็นค่าเริ่มต้น และความเร่งด่วนคิดจากของในคลังเท่านั้น เพื่อไม่ให้ของที่ "ยังไม่ถึง" ทำให้ระบบเลิกเตือนสั่งเพิ่ม
