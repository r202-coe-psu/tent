# CR-212 — ยกเลิกการสมัครจากบัตรดิจิทัล

> **สรุป (TL;DR):**
>
> - **ยกเลิกได้เมื่อ:** ใบสมัครเป็น `confirmed` หรือ `pending_review` และกะยังไม่เริ่ม (เวลาไทย) นอกนั้น `can_cancel = false` และ cancel ได้ 409
> - **token ถาวรของจิตอาสา (CR-127):** เปิดบัตรและยกเลิกได้ โดยระบบเลือกใบที่ยังยกเลิกได้และกะเริ่มเร็วที่สุด
> - **ทางเขียน:** BFF เขียน CouchDB เอง ลำดับคือ กะงาน → คืนโควตา → ใบสมัคร (ขั้นไหนล้มกดซ้ำได้ และกดซ้ำคืนโควตาครบ 1 ที่พอดี — แก้โดย [CR-220](CR-220-ticket-quota-release-marker.md), ดู FR-4) และเลิกส่งต่อไป FastAPI cancel
> - view token จากการค้นด้วยเบอร์ยังยกเลิกไม่ได้เหมือนเดิม (AC-96-03)

---

## Why

- **#967:** เปิดบัตรด้วย token ถาวรของจิตอาสาแล้วกดยกเลิกได้ 404
  - GET หาใบสมัครผ่านจิตอาสาได้ แต่ cancel ส่งต่อไป FastAPI ที่หาจาก token ของใบสมัครใน Mongo อย่างเดียว
  - กะที่ผ่านไปแล้วยังได้ `can_cancel = true`
- **ไม่มีใครเขียน buffer ของ FastAPI แล้ว:** BFF สมัครเขียน CouchDB ตรง FastAPI cancel จึงหาใบสมัครไม่เจอเลย
- **review PR #966:**
  - ถ้า cancel ล้มกลางทาง โควตาค้างถาวร และกดซ้ำไม่ได้
  - token ถาวรหยิบใบสมัครใบไหนก็ได้ที่ `_find` คืนมาเป็นใบแรก
  - ขอให้บันทึกกติกาใหม่ เพราะ CR-096 AC-96-04 ยังเขียนว่า tracking token ได้ `can_cancel = true` เสมอ

## Change

### FR

- **FR-1 resolve token** (ใช้ร่วมกันทั้ง GET และ cancel):
  - หาจาก `tracking_token_hash` ของใบสมัครก่อน หรือ `tracking_token` plaintext ของใบเก่าและใบที่เจ้าหน้าที่สร้าง (legacy ตาม `schema.md` §`job_application` แบบเดียวกับ GET เดิม)
  - ถ้าไม่เจอ หาจิตอาสาที่ token ตรง (token ถาวร CR-127) แล้วเลือกใบสมัครของคนนั้น
    - ใบที่ยังยกเลิกได้ (FR-2) และกะเริ่มเร็วที่สุด กะที่เริ่มไปแล้ว (รวมกะที่กำลังทำอยู่) จึงไม่ถูกเลือก
    - ถ้าไม่มีใบแบบนั้น ใช้ใบล่าสุดตามวันกะ แล้วตาม `created_at`
  - GET คืน `application_id` ของใบที่บัตรแสดง และ cancel ส่ง `application_id` นั้นกลับใน body
    - cancel ทำกับใบนั้นเท่านั้น และต้องเป็นใบของ token นี้ (ใบของ tracking token หรือใบของจิตอาสาเจ้าของ token ถาวร) ไม่อย่างนั้น 409 `NOT_CANCELLABLE` และไม่เขียนอะไร
    - กันกรณี token ถาวรที่ใบที่บัตรแสดงเปลี่ยนไประหว่างเปิดบัตรกับกดยกเลิก (บัตรค้าง) ไม่ให้ยกเลิกใบอื่นที่ผู้ใช้ไม่เห็น
- **FR-2 เงื่อนไขยกเลิก:**
  - `status ∈ {confirmed, pending_review}`
  - เวลาปัจจุบันยังไม่ถึงเวลาเริ่มกะ (`selected_shift.date` + `start_time`, Asia/Bangkok)
  - ใบที่ไม่มี `selected_shift.date` หรือวันกะอ่านไม่ได้ ถือว่ากะเริ่มแล้ว ยกเลิกไม่ได้
  - กะงานที่ผูกกับใบเป็น `checked_in` หรือ `completed` แล้ว (เช่นเช็คอินก่อนเวลาเริ่มกะภายในช่วง grace) ถือว่ากะเริ่มแล้ว ยกเลิกไม่ได้
  - `can_cancel` ใน GET คืนตามเงื่อนไขนี้
  - หลังกะเริ่ม จิตอาสายกเลิกจากบัตรไม่ได้ ให้เจ้าหน้าที่ยกเลิกกะงาน / mark no-show (CR-104 §3.5) แทน
  - ใช้ร่วมกับ `draft-close-ended-volunteer-shifts` (PR #997) ที่ให้สมัครได้จนจบกะ: คนที่สมัครระหว่างกะยกเลิกจากบัตรไม่ได้ — ยอมรับพฤติกรรมนี้
- **FR-3 error:**

  | กรณี                                                                                                 | ผล                     |
  | ---------------------------------------------------------------------------------------------------- | ---------------------- |
  | สถานะไม่ผ่าน FR-2 (รวมยกเลิกซ้ำ) — ยกเว้นใบที่ยังค้างคืนโควตา ซึ่งทำต่อแล้วตอบสำเร็จ (แก้โดย CR-220) | 409 `NOT_CANCELLABLE`  |
  | `application_id` ไม่ใช่ใบของ token หรือไม่ได้ส่งมา                                                   | 409 `NOT_CANCELLABLE`  |
  | สถานะใบสมัครเปลี่ยนระหว่างคำขอ (เช่นเจ้าหน้าที่อนุมัติ)                                              | 409 `NOT_CANCELLABLE`  |
  | กะเริ่มแล้ว, ไม่มีวันกะ หรือกะงานที่ผูกเช็คอินแล้ว                                                   | 409 `SHIFT_STARTED`    |
  | token ไม่พบ หรืออ่านใบสมัครซ้ำไม่ได้                                                                 | 404 `TICKET_NOT_FOUND` |
  | อ่าน/เขียนกะงาน, คืนโควตา หรือเขียนใบสมัครไม่สำเร็จ                                                  | 502 `WRITE_FAILED`     |
  | เขียนกะงานหรือใบสมัครชนกัน (409) ครบ retry                                                           | 409 `WRITE_FAILED`     |
  | error อื่น (เช่น เครือข่าย)                                                                          | 503 `CANCEL_FAILED`    |
  - client ดูจาก `error` ไม่ใช่ HTTP status: `WRITE_FAILED` ทั้ง 502 และ 409 กดซ้ำได้

- **FR-4 ลำดับการเขียน (CouchDB ผ่าน public writer):** หลักคือ ล้มกลางทางแล้วโควตาอาจขาด แต่ห้ามคืนเกิน
  - **ใบที่มีกะงานผูก:**
    1. ยกเลิก `shift_assignment` ที่ผูกกับใบสมัครและยัง `assigned` / `standby` โดยเขียน `status: cancelled` พร้อม `cancel_application_id` = ใบนี้ในครั้งเดียวกัน
    2. คืนโควตา (งานและกะ) เมื่อใบเป็น `confirmed` **และ** มีกะงานที่ผูกซึ่ง `cancelled` พร้อม `cancel_application_id` = ใบนี้ (ยกเลิกในคำขอนี้หรือคำขอก่อนก็ได้) — ledger `job.released_application_ids` กันคืนซ้ำ (แก้โดย CR-220)
    3. เปลี่ยนใบสมัครเป็น `cancelled` (พร้อม `quota_released_at` ถ้าข้อ 2 คืน) เป็นขั้นสุดท้าย
    - ถ้าขั้นไหนล้ม (รวมอ่านกะงานไม่ได้ และเขียนกะงานชนกันครบ retry) ระบบตอบ error ทันทีก่อนแตะใบสมัคร ใบสมัครจึงยังเป็นสถานะเดิม กดยกเลิกซ้ำได้
    - กดซ้ำไม่คืนโควตาซ้ำ เพราะ key ของใบอยู่ใน `job.released_application_ids` แล้ว (แก้โดย CR-220; เดิมเพราะขั้นที่ 1 ไม่พบกะงานที่ต้องยกเลิกอีก)
    - กะงานที่อ่านแล้วพบว่าไม่ใช่ `assigned` / `standby` แล้ว (ถูกเปลี่ยนพร้อมกัน) หรือถูกลบไปแล้ว (404) ข้ามไป ไม่นับว่าล้ม และไม่คืนโควตาให้กะงานนั้น เว้นแต่กะงานนั้น `cancelled` พร้อมตราของใบนี้อยู่แล้ว (นับเป็นค้างคืน)
    - กะงานที่ `cancelled` โดยไม่มี `cancel_application_id` ของใบนี้ (ถอนตัวจาก portal, เจ้าหน้าที่ถอดออก, ข้อมูลเดิม) ไม่นับว่าค้างคืน เพราะทางนั้นคืนโควตาเองแล้ว
  - **ใบที่ไม่มีกะงานผูก** (เช่นใบที่ไม่มี `volunteer_id` หรือหากะที่ตรงไม่ได้ ซึ่งอนุมัติผ่าน `confirmSlot`):
    1. เปลี่ยนใบสมัครเป็น `cancelled` ก่อน (เขียนพร้อม `_rev` cancel ที่ชนกันจะอ่านใหม่แล้วเจอ `cancelled` ได้ 409) และถ้าใบเดิมเป็น `confirmed` เขียน `quota_release_due_at` ในครั้งเดียวกัน (แก้โดย CR-220)
    2. คืนโควตาเฉพาะใบที่เดิมเป็น `confirmed` ผ่าน ledger ของ `job`
    3. เขียน `quota_released_at` บนใบสมัคร
    - กดซ้ำขณะยังมี `quota_release_due_at` และไม่มี `quota_released_at` ทำต่อข้อ 2–3 แล้วตอบสำเร็จ (ไม่ตรวจเวลาเริ่มกะ); เมื่อมี `quota_released_at` แล้วกดซ้ำได้ 409 `NOT_CANCELLABLE` จึงไม่คืนโควตาอีก (แก้โดย CR-220; เดิมใบสมัครที่ `cancelled` เป็นตัวกันการคืนซ้ำเพียงอย่างเดียว)
  - ทั้งสองทาง: ใบสมัครที่สถานะเปลี่ยนไประหว่างคำขอ (เช่นจาก `pending_review` เป็น `confirmed`) ยกเลิกคำขอนั้นโดยไม่เขียนใบสมัคร
  - **ข้อจำกัดที่รู้ — โควตาขาด 1 (D4):** ปิดแล้วโดย [CR-220](CR-220-ticket-quota-release-marker.md) การคืนโควตาล้มแล้วกดซ้ำคืนให้ครบ 1 ที่ · เหลือเฉพาะกรณีที่ CR-220 FR-6 ระบุ (ใบที่มีกะงานผูกซึ่งคืนล้มแล้วกะเริ่มก่อนกดซ้ำ → 409 `SHIFT_STARTED` เจ้าหน้าที่ปรับตัวนับเอง) และใบที่ยกเลิกก่อน deploy CR-220
- **FR-5:** view token จากการค้นด้วยเบอร์ยังได้ `can_cancel = false` และ cancel ได้ 404 (AC-96-03 เดิม)
- **FR-6:** BFF ไม่ส่งต่อ cancel ไป FastAPI แล้ว ส่วน route `/public/v1/volunteer/ticket/{token}/cancel` ของ FastAPI ยังอยู่แต่ไม่มีใครเรียก ให้ลบใน follow-up

## Acceptance

- **AC-1:** token ถาวรที่มีใบอนาคต 2 ใบ เปิดบัตรแล้วเห็นใบที่เริ่มเร็วกว่า ยกเลิกแล้วรีเฟรชจะเห็นใบถัดไป · ถ้ามีกะที่กำลังทำอยู่ด้วย บัตรไม่เลือกกะนั้น
- **AC-2:** ใบ `confirmed` ยกเลิกแล้วโควตาคืน 1 ครั้ง ยกเลิกซ้ำได้ 409 และโควตาไม่เปลี่ยน (คงเดิมเมื่อคืนสำเร็จในครั้งแรก — CR-220 ตรวจเพิ่มด้วย `released_application_ids` / `quota_released_at`)
- **AC-3:** คืนโควตาล้ม ได้ 502 และกดซ้ำแล้วโควตาคืนครบ 1 ที่ ไม่เกินและไม่ขาดไม่ว่ากดซ้ำกี่ครั้ง (แก้โดย [CR-220](CR-220-ticket-quota-release-marker.md) AC-1–AC-3; เดิมอาจขาด 1 ตามข้อจำกัดที่รู้ใน FR-4)
  - ใบที่ไม่มีกะงานผูก: ใบสมัครเป็น `cancelled` + `quota_release_due_at` กดซ้ำสำเร็จและได้ `quota_released_at` ถ้ากดซ้ำอีกได้ 409 `NOT_CANCELLABLE`
  - ใบที่มีกะงานผูก: ใบสมัครยังเป็นสถานะเดิม กดซ้ำสำเร็จ คืนโควตาครบ 1 ที่ ใบเป็น `cancelled` + `quota_released_at` กดซ้ำอีกได้ 409
- **AC-4:** กะที่เริ่มแล้ว และใบที่ไม่มีวันกะ ได้ `can_cancel = false` และ cancel ได้ 409 `SHIFT_STARTED`
- **AC-5:** อ่านกะงานไม่ได้ (502) หรือเขียนกะงานชนกันครบ retry (409) ได้ `WRITE_FAILED` ใบสมัคร กะงาน และโควตาไม่เปลี่ยน
- **AC-6:** cancel ที่ส่ง `application_id` ของใบที่ไม่ใช่ของ token หรือไม่ใช่ใบที่ token ถาวรแสดงอยู่ ได้ 409 `NOT_CANCELLABLE` และไม่เขียนอะไร
- **AC-7:** กะงานที่ผูกเป็น `checked_in` (เช็คอินก่อนเวลาเริ่มกะ) cancel ได้ 409 `SHIFT_STARTED` และไม่เขียนอะไร
