# แบบประเมิน Daily SOP ประจำวันแยกตามหน้าที่

## สรุป

เปลี่ยนจากแบบประเมินเดิมที่รวมหลายหน้าที่ไว้ในชุดเดียว มาเป็นแบบตรวจรายวันแยกตามหน้าที่ 9 Role
รวม 91 ข้อ แต่ละข้อเลือกผลได้ 3 สถานะ: **ผ่าน / ไม่ผ่าน / รอตรวจ**
และบันทึกหมายเหตุเมื่อเลือกไม่ผ่านหรือรอตรวจ

Question Bank ที่ใช้กับแบบตรวจอยู่ใน [เอกสารแนบ A — Question Bank Daily SOP แยกตามหน้าที่](./attachment-daily-sop-question-bank.md)

| หน้าที่                                 | จำนวนคำถาม |
| --------------------------------------- | ---------: |
| ผู้จัดการศูนย์พักพิง (SM)               |         10 |
| ลงทะเบียนและข้อมูลผู้พักพิง (REG)       |         10 |
| คัดกรองและกลุ่มเปราะบาง (TRG)           |          8 |
| การแพทย์และสุขภาพ (MED)                 |         10 |
| ครัวและโภชนาการ (KS)                    |         10 |
| คลัง พัสดุ และการแจกจ่าย (SC)           |         10 |
| อาสาสมัครและกำลังคน (VC)                |          8 |
| ความปลอดภัย (SO)                        |         10 |
| สถานที่ พื้นที่พัก และสาธารณูปโภค (FAC) |         15 |
| **รวม**                                 |     **91** |

## เหตุผล

การตรวจรายวันควรให้ผู้รับผิดชอบแต่ละงานประเมินส่วนที่ตนดูแลได้โดยตรง เช่น ทะเบียน คลัง ครัว
สุขภาพ ความปลอดภัย และสถานที่ ผู้จัดการศูนย์ดูภาพรวมจากความคืบหน้าและข้อที่ต้องติดตาม
โดยไม่ต้องลงผลซ้ำ และไม่รวมทุกข้อเป็นคะแนนเดียวจนความเสี่ยงสำคัญถูกกลบ

## ขอบเขตที่เสนอ

1. เปิดหน้าแรก Daily SOP เป็นรายการความคืบหน้ารายวัน เรียงวันที่ล่าสุดก่อน; เลือกดูได้เฉพาะวันที่ปัจจุบันหรือวันที่ผ่านมา ไม่มีการเลือกวันล่วงหน้า
2. ในแต่ละหน้าที่แสดงจำนวนข้อที่ตอบแล้ว จำนวนข้อทั้งหมด เปอร์เซ็นต์ความคืบหน้า สถานะ และผลผ่าน/ไม่ผ่าน/รอตรวจ; เลือกหน้าที่เพื่อเปิดแบบตรวจหรือทำต่อ
3. แสดงคำถามรายหน้าที่พร้อมตัวเลือก **ผ่าน / ไม่ผ่าน / รอตรวจ** และสถานะความคืบหน้าของชุดตรวจ
4. ออกแบบจากจอมือถือก่อน: คำถามใช้ความกว้างเต็มแถว แล้วตามด้วยตัวเลือกสถานะสามช่องที่มีป้ายกำกับและพื้นที่แตะเพียงพอ; จอแท็บเล็ตและคอมพิวเตอร์แสดงตัวเลือกเป็นคอลัมน์แบบตาราง
5. แสดงชื่อที่ใช้ในระบบของผู้บันทึกล่าสุดและวัน–เวลาในแต่ละข้อเมื่อมีผลบันทึกแล้ว; เมื่อมีการบันทึกทับให้แสดงชื่อและเวลาของผู้บันทึกล่าสุด โดยไม่แสดงประวัติการแก้ไขย้อนหลัง
6. หมายเหตุบังคับสำหรับ “ไม่ผ่าน” และ “รอตรวจ”; ช่องรายละเอียดและค่าที่ตรวจได้เป็นข้อมูลเพิ่มเติม ไม่บังคับกรอก ระบบคำนวณผลเมื่อมีค่าครบและเตือนเมื่อผลคำนวณไม่ตรงกับสถานะที่เลือก
7. คำถามเชิงตัวเลขใช้ค่าจาก SOP Parameter ของศูนย์โดยตรงและแสดงค่าที่ใช้กับคำถาม เช่น `m2_per_person_living` สำหรับพื้นที่พักอาศัยสุทธิในสภาพอากาศร้อน ค่าโครงการที่ยืนยันไว้คือ **3.5 ตร.ม./คน**
8. หากคำถามต้องใช้ Parameter แต่ไม่มีค่าของศูนย์ ให้เลือกได้เฉพาะ “รอตรวจ” จนกว่าจะมีค่าที่ใช้ตรวจได้; ห้ามแทนค่าที่ขาดด้วยค่าคาดเดา
9. สรุปผลเป็นจำนวนผ่าน ไม่ผ่าน รอตรวจ และยังไม่ตอบ พร้อมแสดงข้อที่ต้องติดตาม โดยไม่มีคะแนนรวมข้ามหน้าที่

## Question Bank และการบันทึกค่า

เอกสารแนบ A เป็นชุดคำถาม 91 ข้อที่ใช้อยู่ เรียงตามหน้าที่และรหัสคำถาม; เพิ่ม ลด หรือเรียงคำถามได้สำหรับเอกสารใหม่โดยไม่เปลี่ยน snapshot ของผลตรวจเดิม
แสดงถ้อยคำตามที่ระบบใช้ โดยคำถามบางข้อเติมค่า Parameter ปัจจุบันของศูนย์ก่อนแสดงผล

สำหรับข้อที่มีการคำนวณ ระบบแสดงช่องตัวเลขที่เกี่ยวข้อง เช่น จำนวนผู้พักพิง พื้นที่ ห้องน้ำ
จุดจ่ายน้ำ หรือจำนวนรายการที่ต้องติดตาม ผู้ตรวจกรอกหรือเว้นว่างได้ ช่องเหล่านี้ใช้ช่วยเทียบกับเกณฑ์
และไม่แทนสถานะที่ผู้ตรวจเลือกเอง ทั้งนี้หมายเหตุยังจำเป็นเมื่อเลือก “ไม่ผ่าน” หรือ “รอตรวจ”

Question Bank สำหรับหน้าแบบประเมินไม่มีแหล่งอ้างอิงหรือข้อความวิธีตรวจแสดงต่อผู้ใช้ตามขอบเขตที่ตกลง
ไม่เพิ่มค่าเกณฑ์ที่ไม่มี Parameter หรือค่าที่โครงการกำหนดไว้

## ข้อมูลและผลกระทบ

- เพิ่มเอกสาร `daily_sop_role_assessment` รุ่น `schema_v: 1` หนึ่งรายการต่อศูนย์ ต่อวัน และต่อหน้าที่
  โดยใช้รหัสเอกสารแบบกำหนดแน่นอนเพื่อเปิดตรวจต่อหรือแก้ไขชุดเดิมได้
- เอกสารเก็บ snapshot ของถ้อยคำคำถาม ค่าพารามิเตอร์ และข้อมูลคำนวณที่ใช้ในวันตรวจ เพื่อให้เปิดดูผลย้อนหลังได้
- schema รุ่นนี้ยังเก็บ `check_method`, `pass_criteria` และ `record_values` ไว้ในข้อมูล snapshot ตามสัญญาข้อมูลที่กำลังใช้อยู่ แต่หน้าแบบตรวจไม่แสดงช่องเหล่านี้; Question Bank แนบจึงแสดงเฉพาะคำถามและช่องตัวเลขเพิ่มเติมที่ผู้ตรวจกรอกได้
- เอกสารประเมินใหม่ใช้ชนิด `daily_sop_role_assessment` และแยกตามศูนย์ วันที่ และ Role
- ผู้ปฏิบัติงานประเมิน Role ที่รับผิดชอบได้; ผู้จัดการศูนย์และผู้ดูแลระบบแก้ผลได้ทุก Role ในวันปัจจุบัน สมาชิกศูนย์ทุกคนเปิดดู Review ของทุก Role ในวันย้อนหลังได้ แต่แก้ไขไม่ได้
- แต่ละข้อเก็บบัญชีผู้ใช้ ชื่อที่แสดง และเวลาของผู้บันทึกล่าสุด การบันทึกคำตอบข้อหนึ่งไม่เปลี่ยนข้อมูลผู้บันทึกของข้ออื่น
- ระบบยอมรับการบันทึกเฉพาะวันที่ปัจจุบันตามเวลา Asia/Bangkok ทั้งที่หน้าจอ ระบบบันทึก และตัวตรวจเอกสารของฐานข้อมูล
- ภาพรวมแสดงผลแยกตามหน้าที่และแยกจำนวนตามสถานะ ไม่มีคะแนนหรือสถานะรวมชุดเดียว
