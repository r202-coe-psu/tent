# draft-meal-coverage-report — การรับอาหารประจำวัน

> **สรุป (TL;DR):**
>
> - **เปลี่ยนอะไร:** แท็บที่ 4 "การรับอาหาร" ใน `/back-office/evacuee-management` (`?tab=meals`) ต่อวันที่เลือก แสดง (1) อาหารที่แจกแล้วเทียบกับที่ครัวทำได้ รายมื้อ (2) คนที่มีบันทึกรับอาหาร รายมื้อ (3) ภาพรวมรายโซนและอันดับผู้แจก (4) รายชื่อคนในฐานคน (ผู้พักพิง จิตอาสา เจ้าหน้าที่) พร้อมความคืบหน้า N/2 โดยเรียงผู้ที่ **ยังไม่มีบันทึกรับอาหารครบ 2 มื้อ** ขึ้นก่อน
> - **เพื่อใคร:** ผู้จัดการศูนย์และเจ้าหน้าที่ทะเบียน ดูเรื่องคนในศูนย์ (ผู้พักพิง จิตอาสา เจ้าหน้าที่) ที่หน้าเดียว และตามตัวผู้ที่อาจตกหล่น พร้อมตัวกรอง ค้นหา แบ่งหน้า export CSV และลิงก์ไปข้อมูลรายคน
> - **ข้อมูล:** อ่าน `distribution_log` + `movement` + `evacuee` + `meal_service` + `meal_service_receipt` เดิม และ `shift_assignment` ของวันที่เลือก + รายชื่อเจ้าหน้าที่จาก endpoint เดิม ไม่มี schema ใหม่ ไม่ bump `schema_v`; เพิ่ม Mango index 1 ตัว
> - **owner ตัดสินแล้ว 2026-11-12:** รวมจิตอาสา/เจ้าหน้าที่ในฐานคน (FR-MCR-09), CSV ต้องมี audit แบบ CR-232 (FR-MCR-50), ตัดป้าย "ครัวเรือนมีบันทึกรับ" ทิ้ง (FR-MCR-22) ส่วน PR #1318 ต้องปรับตามสามข้อนี้
> - **ยังรอ owner:** ค่าเริ่มต้นข้ออื่นใน Decision log (ข้อ 3 และ 8 เปลี่ยนผู้ที่เข้าถึงรายงานได้)

---

## Why

- ไม่มีหน้าไหนบอกว่าผู้พักพิงคนไหนยังไม่มีบันทึกรับอาหารครบ 2 มื้อใน 1 วัน (issue #1300)
- รายชื่อเต็มศูนย์มีหลายร้อยคน จึงต้องกรอง ค้นหา และแบ่งหน้าได้ และต้องส่งต่อรายชื่อให้คนเดินตามตัวได้
- บันทึกการแจกไม่ครบเสมอ (แจกโดยไม่สแกน) หน้าจึงต้องบอกข้อจำกัดของตัวเลขให้เห็น (รับแทนครัวเรือนลง log รายสมาชิกแล้วตาม CR-240)
- ไม่มีหน้าไหนบอกสัดส่วนอาหารที่แจกไปแล้ว (issue #1257)
- ผู้จัดการศูนย์ดูข้อมูลคนในศูนย์ที่ `/back-office/evacuee-management` อยู่แล้ว รายงานนี้จึงอยู่หน้าเดียวกัน ไม่แยกไปอยู่หน้าพัสดุ (review comment ใน PR #1363)
- #1257 และ #1300 ใช้ข้อมูลชุดเดียวกันและตอบคำถามต่อเนื่องกัน: อาหารแจกออกไปเท่าไร → ถึงผู้พักพิงกี่คน → ใครยังไม่ได้

## Impact

- แท็บอ่านอย่างเดียว ยกเว้นการเขียน `audit` ตอน export CSV (FR-MCR-50); ไม่กระทบ worker / public plane / FastAPI
- เพิ่ม Mango index 1 ตัวใน shelter DB ผ่าน `redeploy-access.ts` (deploy ต้องรัน `pnpm redeploy:access`)
- แท็บโหลด `evacuee`, `movement` ทั้งศูนย์ (hook เดิม) และ `distribution_log` เฉพาะวันที่เลือก; แบ่งหน้าฝั่ง client เพราะรายชื่อคือผลต่างของสองชุดข้อมูล
- อ่าน `meal_service` / `meal_service_receipt` ผ่าน barrel ของ feature `kitchen`; hook โหลดทุกครั้งที่เปิดแท็บ
- CSV มีชื่อ (PII ระดับชื่อ) ผู้ใช้ที่เข้าแท็บได้ทุกคน export ได้ — ผู้ใช้กลุ่มนี้เข้าถึง PII ของผู้พักพิงในหน้าเดียวกันอยู่แล้ว; ทุกการ export เขียน `audit` fail-closed (FR-MCR-50) ซึ่งเป็น **write** ลง shelter DB (เดิมระบุว่าอ่านอย่างเดียว)
- ฐานคนรวมจิตอาสา → อ่าน `shift_assignment` ของวันที่เลือกเพิ่ม (FR-MCR-09); ต้องตรวจว่า query/index ที่มีรองรับ (`date`) หรือเพิ่ม index
- PR #1318 ต้องปรับตามคำตัดสินสามข้อ: ฐานคนรวมจิตอาสา/เจ้าหน้าที่, ตัดป้ายครัวเรือน (FR-MCR-22) และเขียน audit ก่อน export
- ผู้เข้าถึงรายงานเปลี่ยน: เพิ่ม `registration_staff`, ตัดผู้ที่มีเฉพาะ capability ฝั่งพัสดุ (FR-MCR-28) ไม่แก้ guard หรือ role-permission-matrix ใด
- สัดส่วนรายมื้อใช้ข้อมูลที่แท็บโหลดอยู่แล้ว ไม่เพิ่ม index หรือ BFF; ผล `meal_service` ถูกใช้ทุกโหมด (เดิมใช้เฉพาะโหมดวันนี้)
- `/back-office/distribution` และ `pool-url-state` ไม่เปลี่ยนจาก `develop`
- การ์ดรายโซนและผู้แจกคำนวณฝั่ง client จากข้อมูลชุดเดียวกับตาราง ไม่เพิ่ม query; ชื่อผู้แจกแสดงเป็น username ไม่อ่าน `_users`; ฐานคนเพิ่ม 2 แหล่ง: query `shift_assignment` ของวันที่เลือก และเรียก endpoint รายชื่อเจ้าหน้าที่เดิม (ไม่เพิ่ม field ไม่เปลี่ยน endpoint)
- Seed: `scripts/seed/distribution.ts` เพิ่ม log ย้อนหลัง 1 วัน เพื่อให้แท็บมีข้อมูลบน seed ใหม่

## Out of scope

- รายงานการไหลของ stock อาหาร (ได้รับมา / ส่งครัว / โอนออก / สูญเสีย / คงเหลือ จาก `stock_ledger`) ตามร่างแรกใน issue #1257 — เป็นงานฝั่งคลัง ใช้ข้อมูลและ role คนละชุด ต้องเป็น issue แยกใต้ `/back-office/supply`
- แนวโน้มหลายวัน และการแยกรายโซนในกราฟ
