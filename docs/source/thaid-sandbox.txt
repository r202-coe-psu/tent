1. บทนำ
================================================================================
1.1 หลักการและเหตุผล
เพื่อพัฒนาระบบการปฏิบัติงาน IdP ในการพิสูจน์และยืนยันตัวตนทางดิจิทัล และการให้บริการประชาชนที่มีความน่าเชื่อถือตามมาตรฐานสากล

1.2 วัตถุประสงค์
เพื่อให้หน่วยงานผู้ใช้บริการเข้าใจการทำงานของระบบ IdP ของกรมการปกครอง และสามารถพัฒนาหรือเริ่มต้นศึกษาแนวทางปฏิบัติเบื้องต้นได้

2. สถาปัตยกรรมระบบ
================================================================================
2.1 สถาปัตยกรรมการให้บริการข้อมูลผ่าน BORA API

ภาพรวมกระบวนการ Login by ThaID (OAuth2):
- ผู้ใช้งาน (User)
- แอปพลิเคชัน ThaID (Mobile App)
- แอปพลิเคชันผู้ให้บริการภายนอก (3Party App)
- ส่วนแสดงผล DIMS (DIMS Display)
- ระบบ DIMS (DIMS)

ลำดับขั้นตอนการทำงาน:
1. User เปิดแอปพลิเคชัน -> 3Party App
2. 3Party App ส่ง Request Login by ThaID ไปยัง DIMS ด้วย Request login URL พร้อม Query String
   Query String ประกอบด้วย:
   - scope
   - response_type
   - client_id
   - redirect_uri
   - state (*optional)
   Request login URL:
   https://imauthsbx.bora.dopa.go.th/api/v2/oauth2/auth/?response_type=code&client_id={{client_id}}&redirect_uri={{redirect_uri}}&scope={{scope}}&state={{state}}
3. DIMS ทำการ Generate web QRCode แล้ว Redirect ไปที่ DIMS Display เพื่อแสดง Web Login (QRCode)
4. User ใช้ (Mobile App) ThaID ทำการสแกน QR Code (Scan login)
5. DIMS ทำการ Update Scan Status และส่งคำสั่งให้ DIMS Display ทำการ Blur QRCode
6. User ป้อน Pin 8 Digit บน Mobile App ThaID และกดยินยอม (Consent)
7. DIMS ทำการ Update Consent Status
8. DIMS ส่ง Callback Authorization Code กลับมายัง 3Party App
9. 3Party App นำ Authorization Code ไปขอ Token (Get token) จาก DIMS
10. DIMS ตรวจสอบและ Generate Token ส่ง Token result กลับมายัง 3Party App
    Token result ประกอบด้วย:
    - token (access_token)
    - refresh token
11. 3Party App เข้าสู่ระบบสำเร็จ (Login success) และดำเนินขั้นตอนตาม 3Party App flow ต่อไป

| หัวข้อ | ข้อกำหนด |
| :--- | :--- |
| 1 การลงทะเบียนขอใช้งาน | หน่วยงานต้องมีหนังสือขออนุญาตการใช้งานแอปพลิเคชัน ThaID และมอบหมายผู้ประสานงานระหว่างหน่วยงานกับกรมการปกครองในการพัฒนา รวมไปถึงการเพิ่มเจ้าหน้าที่/ผู้พัฒนาแอปพลิเคชันของหน่วยงาน ซึ่งต้องได้รับการอนุญาตจากอธิบดีกรมการปกครองแล้วเท่านั้น |
| 2 ผู้ขอใช้งาน | กรมการปกครองขอสงวนสิทธิในการอนุมัติ/อนุญาต การขอใช้งานสำหรับผู้ใช้งานของหน่วยงานภายนอก โดยจะทำการพิจารณาจากเอกสารของหน่วยงาน และการยืนยันจากผู้ประสานงานของหน่วยงานนั้น ๆ |

4. ขั้นตอนการขอใช้บริการข้อมูล
================================================================================
หน่วยงานที่ต้องการใช้บริการแอปพลิเคชัน ThaID สามารถดำเนินการขอใช้บริการได้ดังนี้:

1) เข้าสู่เว็บไซต์ https://digitalid.bora.dopa.go.th เพื่อขอลงทะเบียนหน่วยงาน และสามารถเพิ่มเจ้าหน้าที่ผู้รับผิดชอบในการพัฒนาแอปพลิเคชันของหน่วยงานได้ไม่เกิน 10 คน ในการขอใช้งานระบบ (เริ่มต้นให้บริการ 1 กุมภาพันธ์ 2564)
2) พิมพ์แบบฟอร์มจากระบบ และจัดทำหนังสือราชการส่งถึงกรมการปกครอง (หนังสือที่ส่งถึงกรมการปกครอง ต้องระบุข้อมูลผู้ประสานงานให้ชัดเจน เช่น เลขประจำตัวประชาชน, ชื่อ-นามสกุล, ตำแหน่ง, หมายเลขโทรศัพท์ที่ติดต่อได้, อีเมล เป็นต้น เพื่อให้กรมการปกครองสามารถติดต่อสอบถามข้อมูล/ประสานงานได้โดยง่าย) หนังสือราชการจะต้องลงนามโดยผู้มีอำนาจลงนามของหน่วยงาน โดยกรมการปกครองจะใช้ในการพิจารณาอนุญาต/ไม่อนุญาต ให้หน่วยงานสามารถพัฒนาแอปพลิเคชัน และเชื่อมโยงกับกรมการปกครองในการพิสูจน์และยืนยันตัวตนผ่านแอปพลิเคชัน ThaID ได้หรือไม่
3) เมื่อเจ้าหน้าที่ของกรมการปกครองพิจารณา อนุญาตหรือไม่อนุญาต จะส่งข้อความแจ้งเตือนผ่านแอปพลิเคชัน (ThaID) เพื่อแจ้งให้ทราบ
4) เมื่อได้รับอนุญาตให้ใช้งาน หน่วยงานสามารถขอเพิ่มระบบงานบริการได้ด้วยตนเอง และจะได้รับข้อมูลเพื่อนำไปใช้ในการพัฒนาระบบให้บริการของตนเอง

6.1 Authentication
--------------------------------------------------------------------------------

6.1.1 Authentication Request
Web Application/Mobile Application ของ RP จะส่ง authentication request ด้วย HTTPS GET request ไปยัง https://imauthsbx.bora.dopa.go.th/api/v2/oauth2/auth/

ค่าพารามิเตอร์ของ Authentication Request:
| พารามิเตอร์ | รายละเอียด |
| :--- | :--- |
| response_type | ระบุค่าเป็น “code” เนื่องจากเป็นการร้องขอสิทธิการเข้าถึงข้อมูล แบบ authorization code |
| client_id | ระบุค่า client identifier ที่กรมการปกครองออกให้กับ RP ที่ผ่านการลงทะเบียนแล้ว |
| redirect_uri | ระบุค่า URI ที่ RP ลงทะเบียนไว้กับกรมการปกครอง เพื่อใช้ในการรับ authorization code |
| scope | ระบุ scope ข้อมูลที่ต้องการขอเข้าถึงจากผู้ใช้บริการ (มี 20 รายการ ดูรายละเอียดด้านล่าง) |
| state | random string ใช้ในการตรวจสอบความสัมพันธ์ระหว่าง request จาก RP กับ response จาก server ของกรมการปกครอง |

รายละเอียดค่า Scope (20 รายการ):
(1) pid : หมายเลขประจำตัวประชาชน 13 หลัก
(2) name : ชื่อ-นามสกุล ภาษาไทย
(3) name_en : ชื่อ-นามสกุล ภาษาอังกฤษ
(4) birthdate : วัน เดือน ปี ค.ศ. เกิด (เช่น 1989-12-28)
(5) address : ที่อยู่ตามหน้าบัตรประจำตัวประชาชน
(6) given_name : ชื่อ ภาษาไทย
(7) middle_name : ชื่อกลาง ภาษาไทย
(8) family_name : นามสกุล ภาษาไทย
(9) given_name_en : ชื่อ ภาษาอังกฤษ
(10) middle_name_en : ชื่อกลาง ภาษาอังกฤษ
(11) family_name_en : นามสกุล ภาษาอังกฤษ
(12) gender : เพศ (เช่น male)
(13) smartcard_code : เลขใต้รูป
(14) title : คำนำหน้านามภาษาไทย
(15) title_en : คำนำหน้านามภาษาอังกฤษ
(16) ial : ระดับความเข้มข้นในการพิสูจน์ตัวตน
(17) date_of_issuance : วันที่ออกบัตร
(18) date_of_expiry : วันที่บัตรหมดอายุ
(19) house_address : ที่อยู่ตามทะเบียนบ้าน โดย formatted คือ ที่อยู่ที่จัดรูปแบบแล้ว, raw คือที่อยู่คั่นด้วย # (เลขที่#หมู่ที่#ตรอก#ซอย#ถนน#ตำบล#อำเภอ#จังหวัด)
(20) openid : id_token ที่มีข้อมูลผู้ใช้บริการที่ RP ร้องขอ

หมายเหตุ: หากมีข้อมูลหลายอัน ให้แยกข้อมูลแต่ละอันด้วยการเว้นวรรค 1 วรรค (หรือ %20 ในระบบ Base64 url encoded)

ตัวอย่างการใช้งาน Authentication Request:
Method: GET
URL: https://imauthsbx.bora.dopa.go.th/api/v2/oauth2/auth/?response_type=code&client_id={{clientIdFromDOPA}}&redirect_uri=https://rp.example.org/api/callback&scope=pid%20name%20birthdate%20openid&state=af0ifjsldkj
Header:
Content-Type: application/x-www-form-urlencoded

6.1.2 Authentication Response
Authorization code เป็น credential ที่ออกโดย server ของกรมการปกครองให้กับ Web Application/Mobile Application ของ RP เพื่อใช้เป็นหลักฐานว่าผู้ใช้บริการได้ผ่านการยืนยันตัวตนและให้ความยินยอมในการเปิดเผยข้อมูลแล้ว server ของกรมการปกครองจะส่ง authorization code ให้กับ Web Application/Mobile Application ของ RP ด้วยการส่ง HTTPS response กลับไปยัง redirect URI ตามที่ลงทะเบียน

ค่าพารามิเตอร์ของ Authentication Response:
| พารามิเตอร์ | รายละเอียด |
| :--- | :--- |
| code | authorization code เพื่อใช้ในการร้องขอ access token |
| state | state เป็นค่าเดียวกันกับ state ใน authentication request |

ตัวอย่างการใช้งาน Authentication Response:
Response Status: 302 Found
Payload / Redirect URL:
https://rp.example.org/api/callback?code=nnqtYcoik7cjtHQYyn3Af8uk4LG3rYYh&state=af0ifjsldkj

6.1.3 Authentication Error Response
หากมีข้อผิดพลาดในกระบวนการยืนยันตัวตนนอกเหนือจากปัญหาจาก redirect URI เช่น ผู้ใช้งานไม่ผ่านการยืนยันตัวตน หรือไม่ยินยอมที่จะเปิดเผยข้อมูล server ของกรมการปกครองจะแจ้ง error code ให้กับ Web Application / Mobile Application ของ RP ด้วยการส่ง HTTPS response กลับไปยัง redirect URI ตามที่ลงทะเบียนไว้

ค่าพารามิเตอร์ของ Authentication Error Response:
| พารามิเตอร์ | รายละเอียด |
| :--- | :--- |
| error | error code แจ้งสาเหตุของข้อผิดพลาดที่เกิดขึ้น (อ้างอิงหัวข้อที่ 7) |
| error_description | คำอธิบาย error code ในรูปแบบ text |
| error_uri | URI ที่ระบุข้อมูลเพิ่มเติมของ error อาจเป็น Webpage |
| state | state เป็นค่าเดียวกันกับ state ใน authentication request |

ตัวอย่างการใช้งาน Authentication Error Response:
Response Status: 302 Found
Payload / Redirect URL:
https://rp.example.org/api/callback?error=invalid_request&error_description=Unsupported%20response_type&state=af0ifjsldkj

6.2 การขอ Token
--------------------------------------------------------------------------------

6.2.1 Token Request
Web Application/Mobile Application ของ RP ใช้ authorization code เพื่อร้องขอข้อมูลในการยืนยันตัวตน ผู้ใช้บริการจากกรมการปกครอง ด้วยการส่ง HTTPS POST request

ค่าพารามิเตอร์ของ Access Token Request:
| พารามิเตอร์ | รายละเอียด |
| :--- | :--- |
| Authorization | ใช้ค่า “Basic” + Base64({{client_id}}:{{client_secret}}) |
| grant_type | ใช้ค่า “authorization_code” |
| code | authorization code ที่ได้รับมาก่อนหน้า |
| redirect_uri | URI เป็นค่าเดียวกันกับ redirect_uri ใน authentication request |

ตัวอย่างการใช้งาน Token Request:
Method: POST
URL: https://imauthsbx.bora.dopa.go.th/api/v2/oauth2/token/
Header:
{
  "Content-Type": "application/x-www-form-urlencoded",
  "Authorization": "Basic authorization"
}
Body:
grant_type=authorization_code&code=code&redirect_uri=redirect_uri

6.2.2 Token Response
Server ของกรมการปกครองตรวจสอบ authorization code ที่ได้รับ หากถูกต้อง ก็จะส่ง token response พร้อมกับข้อมูลยืนยันตัวตนกลับมายัง web/mobile application ของ RP ด้วยการส่ง HTTPS POST response กลับไปยัง redirect URI ตามที่ระบุใน token request

ค่าพารามิเตอร์ของ Token Response:
| พารามิเตอร์ | รายละเอียด |
| :--- | :--- |
| access_token | String มีอายุ 15 นาที |
| token_type | ใช้ค่า “Bearer” |
| expire_in | วัน เวลาที่ access token หมดอายุ รูปแบบ Unix timestamp (second) |
| scope | scope ของข้อมูลที่ได้รับ |
| *id_token | Option ถ้า scope=openid คือ id_token ที่มีข้อมูลผู้ใช้บริการที่ RP ร้องขอ |
| **scope value | String ที่เก็บ value ของ scope นั้น ๆ |

หมายเหตุ:
* id_token จะเก็บข้อมูลตามมาตรฐาน OpenID Connect โดยสามารถตรวจสอบกระบวนการ verify ได้ที่ https://imauthsbx.bora.dopa.go.th/.well-known/openid-configuration จะ return เฉพาะกรณีกำหนด scope openid เท่านั้น
** scope value เช่น “pid”: “หมายเลขประจำตัวประชาชน 13 หลัก”, “name”: “ชื่อ-นามสกุล ภาษาไทย” เป็นต้น จะ return ให้เฉพาะกรณีไม่กำหนด scope openid

ตัวอย่างการใช้งาน Token Response:

กรณีไม่กำหนด scope openid:
Response Status: 200 OK
Payload:

  "expire_in": 1612857374,
  "access_token": "access_token",
  "refresh_token": "refresh_token",
  "token_type": "Bearer",
  "scope": "pid name",
  "pid": " pid ",
  "name": " name "
}

กรณีกำหนด scope openid:
Response Status: 200 OK
Payload:
{
  "expire_in": 1612857374,

6.2.3 ID Token
id_token จะมีข้อมูลผู้ใช้บริการที่ RP ร้องขอ มีอายุใช้งานตามที่กำหนด มีการลง signature จากกรมการปกครอง และมีการเข้ารหัสด้วย Base64

ภายใน id_token จะมีค่าพารามิเตอร์ดังนี้:
| พารามิเตอร์ | รายละเอียด |
| :--- | :--- |
| at_hash | Access Token hash value |
| aud | App ที่สามารถใช้งานได้ |
| exp | วัน เวลา หมดอายุ |
| iat | วัน เวลา ที่ออก token |
| iss | ผู้ที่ออก token |
| sub | Subject Identifier |
| *scope value | String ที่เก็บ value ของ scope นั้น ๆ |

* scope value เช่น “pid” : “หมายเลขประจำตัวประชาชน 13 หลัก”, “name” : “ชื่อ-นามสกุล ภาษาไทย” เป็นต้น
ตัวอย่างข้อมูลผู้ใช้บริการที่ RP ร้องขอใน ID Token:
- pid : pid
- name : name
- birthdate : birthdate

7. ข้อแนะนำ
================================================================================
- Status คือ HTTP Status Code ที่ระบบจะแจ้งกลับ (Response) มายังต้นทางทราบ ดังนี้:

| Code | Response Error | Error Description |
| :--- | :--- | :--- |
| 400 | invalid_request | The require parameter is missing or invalid |
| 400 | invalid_scope | The scope is invalid |
| 400 | invalid_request | The redirect or callback url mismatch or invalid |
| 400 | invalid_request | Invalid Authorization Code |
| 400 | unsupported_response_type | Unsupported response type |
| 400 | unsupported_grant_type | Unsupported grant type |
| 400 | unsupported_token_hint | Unsupported token hint |
| 400 | unsupported_token_type | Unsupported token type |
| 400 | duplicate_request | The duplicate request is not allowed |
| 400 | server_error | Something went wrong, please try again in the moment |
| 401 | unauthorized_client | The client is not authorized |
| 401 | invalid_client | Client id not found |
| 401 | user_denied | User denied the request (disapproved) |
| 401 | invalid_refresh_token | Verify refresh token failed |
| 401 | invalid_refresh_token | Invalid refresh token |
| 401 | invalid_refresh_token | Cannot refresh access token |
| 401 | access_denied | You're not allowed |
| 401 | access_denied | You're not allowed as Authorative Source |
| 401 | access_denied | You don't have permission to access this service |
| 404 | not found data | - |

- Response จะอยู่ในรูปแบบ JSON แต่มีบางคำสั่งจะไม่มีข้อมูลตอบกลับ ขึ้นอยู่กับ Status
- ทุก request parameters จะต้องมีการกำหนดค่า ยกเว้นที่ระบุไว้เป็น [optional]

8. การใช้งานเว็บไซต์เพื่อการยืนยันตัวตนผ่าน Sandbox
================================================================================
ระบบ ThaID Sandbox มีเว็บไซต์สำหรับการยืนยันตัวตน (แทนแอปพลิเคชัน ThaID) ทำให้ผู้พัฒนาสามารถใช้งานระบบได้โดยไม่ต้องติดตั้งแอปพลิเคชัน ThaID

ลักษณะหน้าเว็บยืนยันตัวตน Sandbox:
- URL หน้าล็อกอิน: imauthsbx.bora.dopa.go.th/oauth2/?version=2&txId={txId}&qrcode={qrcode}
- หัวข้อ: เข้าสู่ระบบ ด้วย ThaID sandbox
- ช่องข้อมูล: เลขประจำตัวประชาชน (เช่น 1-2345-67890-12-3)
- ปุ่มดำเนินการ: [ยืนยัน] / [ไม่ยืนยัน]
- ข้อความท้ายหน้า: คิวอาร์โค้ดนี้เป็นสิ่งยืนยันตนทางดิจิทัล ออกให้โดย กรมการปกครอง กระทรวงมหาดไทย (v.0.4.9)

การใช้งาน:
- ผู้ทดสอบสามารถแก้ไขเลขประจำตัวประชาชนได้ตามต้องการ (ส่วนข้อมูลอื่น ๆ ระบบจะกำหนดค่าคงที่ไว้ให้)
- เมื่อกดปุ่ม 'ยืนยัน' ระบบจะส่ง authorization code ให้กับ Web Application / Mobile Application ของ RP ด้วยการส่ง HTTPS response กลับไปยัง redirect URI ตามที่ลงทะเบียนไว้
